# 因子与策略

策略工作台按版本提供搜索、状态筛选和服务端分页，列表展示名称、创建时间、生命周期及关联实盘；查看、编辑、删除为带提示的图标入口。删除前服务端预检所选版本的快速测试及回测数量，二次确认后由业务事务清理该版本、关联任务和回测明细；最后一个版本删除时清理策略定义，其他版本不受影响。快照仅在不再被其他回测引用时删除。任何状态的实盘引用都会阻止删除，并提示关联实盘名称；需要先手动删除相关实盘数据，运行或暂停的实盘须先终止。关联任务执行中不能删除，待任务结束后重试。审计记录保留，删除失败时全部回滚。

## 因子

因子是平台代码内的只读方法，随 Easy Quant 发布，不由用户创建、编辑或单独版本化。因子目录展示说明、参数、输出结构、输出示例和调用示例。示例中的数值和日期仅用于说明返回结构；技术及统计因子的计算结果为 Python `Decimal`，数据不足时通过 `available: False` 与 `required`、`actual` 等字段说明原因。行情和基本面记录的字段会随数据集而不同，策略应先检查记录是否存在。

| 因子 | 当前能力 |
| --- | --- |
| `market.daily-bars` | 读取决策时点可见的日线 K 线 |
| `market.value` | 读取最新可见的估值与市值记录 |
| `technical.ma` | 移动平均线，`window=5` 即 5 日均线 |
| `technical.rsi` | 指定窗口 RSI |
| `technical.macd` | DIF、DEA 与 MACD 柱值 |
| `stat.expected-return` | 历史胜率和预期回报 |
| `fundamental.latest` | 指定基本面数据集的最新可见记录 |
| `fundamental.history` | 指定基本面数据集的可见历史序列 |

机器学习因子只能加载随应用发布且摘要匹配的权重，运行期不训练或上传模型。

## 策略契约

策略必须实现 `before_market(context, parameters)`、`on_market(context, parameters)` 和 `after_market(context, parameters)` 三个钩子。每个钩子返回信号列表；系统不提供旧策略协议兼容入口。信号至少包含 `symbol`、`action`、`quantity` 和 `reason`，盘中条件信号可带 `trigger_price`。

策略上下文提供股票池、当前持仓、盘中价格以及 `factor` 调用。盘前只看到此前已知数据；盘中通过当前报价判断触价；盘后可以读取当日收盘数据。页面提供“5 日均线选股”和“正预期示例”，两者与用户策略使用完全相同的保存、版本和运行机制，使用比例建议。策略公共库嵌入编辑页右侧侧栏，搜索固定在顶部，接口初始折叠；提供签名、参数、返回值、调用示例和运行时限制。窄屏显示在编辑器下方，旧 `/strategy-library` 地址跳转新建编辑页。空白和两个示例位于“代码模板”菜单，确认后才覆盖当前编辑器内容。

三个运行时共用 `RuntimeContext` 和唯一的平台因子实现。`context.position(symbol)` 返回 Decimal 数量，`context.portfolio()` 返回 Decimal 现金、持仓和平均成本。快测和回测按阶段模拟成交，下一阶段看到真实接受的模拟组合；实盘以人工操作账本为准，建议不入账。上下文是独立副本，修改它不会改变引擎账户。

`context.signal(symbol, action, ratio, reason, price=...)` 返回信号字典，需要放入钩子的返回列表。买入比例以阶段开始可用现金为基数，卖出比例以该股实际持仓为基数；比例范围 `(0,1]`，默认按 100 股向下取整，数量为零不执行。买入预留配置中的手续费和滑点，同一钩子中生成的比例建议预留计划预算，避免重复分配；这不会修改真实账本。实盘建议优先采用本阶段临时报价，其次采用信号参考价或已有日线价格；实际入账仍由用户反馈决定。可用 `trigger_operator="lte"` 表达低于阈值卖出，`"gte"` 表达突破买入；省略触发价表示本次直接建议，已有持仓仍可加仓。旧数量信号仍可读取，但新模板使用比例。

`context.store.get/set/delete` 提供跨阶段、跨交易日 KV。快测和回测仅在一次运行内存中保留，实盘按实例持久保存到 MariaDB；阶段成功时与建议原子提交，失败不提交，重试不会重复更新。状态支持 JSON 值和有限 Decimal，Decimal 保存为十进制字符串，读取后可用 `Decimal(value)` 恢复；总量限制 256 KiB。源码全局变量不能替代持久状态。

`context.securities(industry=...)` 查询已知的申万一级行业股票池，`security_info` 读取证券风险/行业快照，`financials` 读取可见财务历史，`valuation` 读取可见估值。历史分类或财报没有可见记录时不补造；ST 标记来自证券名称，未知值为 None。实盘盘中可用 `quotes(symbols)` 批量查询或 `current_price(symbol)` 单股查询，宿主只为请求的股票访问真实接口，同阶段缓存结果。

新建默认为草稿，保存原地更新草稿并验证修订号，不创建额外版本。首次提交回测后锁定为测试中（与入队同事务），进入实盘后标记已实盘（与实例创建同事务）；失败、删除回测或删除实盘均不回退状态。编辑非草稿版本时必须确认，从指定旧版本复制出新的草稿版本；原代码和引用不变。版本号不重用，过期保存及锁定后保存均拒绝。策略在 `python -I` 子进程运行，限制导入和危险内置函数，设置超时、输出上限并过滤敏感环境变量。这适合当前受限可信用户环境，不是强隔离的多租户沙箱。
“运行快速测试”直接执行编辑器当前代码，无需先保存，也不创建版本或改变生命周期。代码仅为排队执行临时传递，成功或失败结束后从任务清除，不保留历史代码快照；结果只留摘要，不能作为实盘启动依据。这是单交易日快速测试：后台 worker 按三个阶段运行并推进模拟组合，展示信号、输出、模拟组合和失败原因；不推进真实持仓、不发送通知。按因子需求读取此前可见历史，MA5 预热 5 个实际交易日，RSI14 预热 15 日；动态窗口、原始日线历史、统计和 EMA 沿用 250 日默认口径，源码声明优先。用户可显式开启 Mock，重复首个可见价格补足技术窗口，结果标记补值次数；不补造财报，不改变正式回测/实盘的数据，不可用作实盘启动依据。默认不开启，数据不足仍明确返回。模拟盘中报价使用当日开收盘均值，包含收盘信息，仅为日线近似。单阶段标准输出上限 64 KiB，策略结果传输上限 8 MiB。

实盘、回测和快测共用历史需求提取：可静态识别的 MA/RSI 使用所有调用所需窗口的最大值；无法确定的动态调用及原始历史、统计、EMA 保留 250 个交易日，避免截断输入改变统计口径。可在源码顶层声明 `HISTORY_TRADING_DAYS = 500`，允许范围为 1–2500，声明优先。保存后产生新的不可变策略版本。窗口限制每个决策日的可见历史，不限制回测整体起止日期：一个有 30 个交易日的 MA5 回测读取区间内 30 日及此前 5 日，而五年回测仍逐日推进完整五年。盘前/盘中仍不得看到当日收盘数据。行情缓存仅在单个任务内有效，默认最多保留 2 个月块，按 LRU 淘汰；批量请求先合并所需缺段，单日缺失预取整月，返回时只提供请求日期，后续仍按可获知时间过滤。不跨任务留存旧页。

原始日线结果仅用于固定末尾索引（如 `bars[-1]` 取最新收盘）时，可静态缩减到实际需要的条数；遍历、动态索引或把完整序列交给其他函数时保留默认窗口。因此现有均线示例的最新价格读取不会把 MA5 预热扩大到 250 日。

快测和回测结果展示阶段耗时及 hook 调用次数、平均/最大耗时，可按交易日查看三个 hook 明细。计时为宿主观测的实际耗时，包含子进程通信，不是纯策略 CPU 时间；失败时保留已完成统计。
