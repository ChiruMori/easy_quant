# 公司行为与复权

平台以不复权日线保存真实成交，以独立事件记录生成研究价格，以权益账本处理实际现金和股数。不能用一条复权价格曲线代替组合账本。

## 当前数据范围

已核对本地数据库的日线 provenance：通达信、AKShare、东方财富及腾讯记录的口径均为 `none`，现有原始价可直接保留，没有重写或清空价格大表。两个单股审计样本 `000001`、`600519` 的公司行为事件及核验覆盖均为空。旧回测和策略源码保持原状，不自动重算或改写。

通达信公开 `gbbq.zip` 中的 `gbbq` 文件现在能够解码；归档同时还包含交易日历。候选保留证券、供应商事件日、类别、Float32 原值的可往返十进制表示、原始文件 SHA256、首次观测时间和内容身份。解析严格验证记录数量、长度、ZIP 成员及数值；不解压或执行归档中的程序。非流通上市、增发、回购等不会直接转换为价格复权事件；未知类别保留待核对。

GBBQ 不提供完整的公告版本、登记日、现金到账日及股份上市日。既有东方财富分红方案也缺少完整到账字段，且方案不等于实施事件。因此这些公开记录目前只进入 `candidate`，不会自动认证历史数据或倒填可获知时间。券商全量日线、个人行情日线及专业财务包的下载页面，也不能作为上述事件字段完整的证明。平台没有接入付费数据源。

**目前没有将全部历史升级为可信数据。** 缺少核验覆盖的正式回测、策略/因子快测、实盘研究会明确失败；Mock 不能绕过公司行为检查。股票详情的默认日线接口仍提供原始事实，浏览原价不代表该区间可用于研究。只有补齐公开实施公告并核实覆盖后，才能启用相应证券、区间；不能把公开接口空响应当作“没有事件”。

## 数值和时点

同一证券、同一除权日的现金、送转、配股等须合并成一个事件。`cash_per_share` 为税前人民币元/原股；`share_multiplier` 为送股、转增、拆合股后的非配股股数/原股，正常为 1，拆股大于 1、合股小于 1；`rights_ratio` 为每原股可配股数，`rights_price` 为配股价。普通参考价为：

```text
reference = (previous_close - cash_per_share + rights_ratio * rights_price)
            / (share_multiplier + rights_ratio)
price_ratio = reference / previous_close
```

交易所批准特殊算法时，可提供公告明确的 `reference_price`；仍须完整说明经济权益。参考价必须为正；事件前收盘价与已读取原价不一致时中止。增发、回购、可转债转股、单纯流通股变化不能仅凭股本数量套用该公式。

事件的 `available_at` 是该**具体版本**可获知的时间，必须带时区；`observed_at` 是本平台观测时间。日期不明确的旧材料不得猜测成历史公告时点。修订追加内容寻址版本，不覆盖旧记录；同一公告时间出现不同内容、登记后权益发生修订均报冲突。公司行为及覆盖存于已有 `market_records`，无新外键、无价格大表迁移。

覆盖证明独立保存 `start_day/end_day`、公开证据、区间内全部事件版本的 `event_keys`、已核对候选的 `resolved_candidate_keys`。它是数据审计元数据，不作为策略经济信息；不能认证尚未发生的未来日期。新事件版本或新候选不在既有核验内时会重新阻断。取消方案或不构成除权的候选，须在 `candidate_resolutions` 中给出 `dismissed:公开证据及说明`，不能为清除阻断伪造实施事件。

## 研究接口

```python
bars = context.history("000001")                    # 默认 qfq
actual = context.history("000001", adjustment="raw")
backward = context.history("000001", adjustment="hfq")
events = context.corporate_actions("000001")
today = context.trading_day()                       # 不触发历史行情读取
```

`history` 为 DataFrame / float64。`qfq` 以当前决策日为锚，将此前已生效事件的 `price_ratio` 累乘到早期 OHLC；`hfq` 以本次窗口首日为基准，对后续 OHLC 乘逆比例。元数据标明 `price_basis`、`adjustment_anchor`、`price_scale`。未来除权不提前生效；晚到且缺少当时可获知版本的已生效事件会中止。子进程只收到决策时点已知的经济版本，完整审计保留在宿主及回测结果。

`raw_open/high/low/close` 保留对应原价；`volume/amount` 保留实际成交股数/元。`adjusted_volume` 仅按股数变化换算（现金分红不会改变它），`adjusted_vwap` 将实际成交额/实际成交量换算到与研究 OHLC 相同的价格尺度。Alpha101 的量和 VWAP、成交量变化回归使用这些派生列；成交额因子保持实际金额。指数不进行股票公司行为复权。

`context.library('market.daily-bars', ...)` 与技术因子采用相同研究视图。成交、`current_price/quotes`、资金及股数账本继续使用真实原价和 Decimal。`context.data['prices'/'bars']` 是兼容的原始输入，不应直接用于跨除权收益或技术因子；新代码使用 `history/library/factor`。

`corporate_actions` 返回已知且已生效事件的 `event_id`、`record_key`、`ex_date`、`price_ratio`、`share_multiplier`、`cash_per_share`。策略保存的价格阈值应按事件幂等调整，不能因每个 hook 重复变换。网格模板会调整其价格锚，并在已处理事件发生修订时要求复核；已有锁定策略须复制草稿自行适配，平台不修改其 KV 或源码。

乘法前后复权收益在同一基准下可比较，**不等于**实际账户现金分红到账后再投资的收益。平台不会自动将分红再投资，也不把税前回测口径冒充个人税后到账。

曲线中的临时股票比较按每个观察时点的已知事件复权，并将起点换算到相同价格基准；现金分红不会产生虚假的价格跌幅。它仍是复权价格收益比较，不是账户税后再投资收益。

日线 API 可显式查询 `?adjustment=qfq|hfq|raw&as_of=带时区ISO时间`；带 `as_of` 的研究请求执行同样校验。默认无参数的 raw 查询保留事实浏览兼容性。

## 回测与实盘权益

回测在登记日收盘锁定权益；除权日确认应收现金及股份，现金到派息日才可用，新增股份到上市日才可卖。拆合股替换股份在上市前锁定。卖出登记日已有股票不丢失已登记分红；除权日新买入不追溯获得分红。停牌期间保留最后价格，并按已知公司行为变换估值基准，避免资产因缺当日 K 线消失。结果保存事件快照、SHA256、组合输入身份及登记/除权/到账/上市流水；股票收益归因包含分红和股份变化。

当前回测现金分红采用税前金额及分币四舍五入，不模拟持有期差异化红利税。持仓配股缺少明确认购/缴款/权益处置模型时中止；产生碎股、缺登记日持仓快照或登记后修订时也中止。价格参考公式支持配股不代表账户已认购，不会凭空增加股份或忽略认购成本。这些场景尚未全自动支持。

实盘按人工已确认操作重建真实账本。实例详情提供按需加载的“公司行为核对”，展示登记数量、税前应得现金、股份增减及到账日期；全部到账后填写实际净现金与不含账号的凭证说明。确认按事件版本幂等记账、保留审计、维持股份变动前后的总成本，并使除权前未处理建议失效。未核对前停止生成建议；未知覆盖、待核对及修订冲突期间不展示可验证收益。公司行为入账不是外部追加资金，也不伪装成买卖成交标记。配股和碎股不能通过这个通用表单跳过核实。

## 一次性整理与持续同步

所有命令均从仓库根运行，默认预览，只有 `--apply` 写入。输出真实资料应放在已忽略的 `backend/.local-data/`，不要提交凭证。

```powershell
pnpm data:corporate-actions audit --symbol 000001 --output backend/.local-data/actions-audit.json
pnpm data:corporate-actions import-gbbq --input backend/.local-data/tdx/daily/gbbq.zip --symbol 000001 --output backend/.local-data/gbbq-preview.json
pnpm data:corporate-actions migrate-dividends --symbol 000001 --output backend/.local-data/dividend-preview.json
# 核对候选后，才明确写入候选；不会新增可信事件、覆盖或改写任何 K 线
pnpm data:corporate-actions import-gbbq --input backend/.local-data/tdx/daily/gbbq.zip --symbol 000001 --apply --output backend/.local-data/gbbq-import.json
```

标准事件文件采用 `schema_version: corporate-actions-v1`，顶层包含 `source`、`evidence`、`events`、`coverage`。事件字段为上文数值，加上 `symbol`、`event_id`（`证券代码:除权日`）、`ex_date`、`record_date`、`available_at`、`status`（implemented/cancelled）、`kinds`、`cash_pay_date`、`shares_listing_date`、`evidence`；可选特殊 `reference_price`。`kinds` 允许 cash_dividend、bonus、capitalization、rights、split、consolidation。缺字段拒绝写入，不猜测日期。

先对 `coverage: []` 的文件运行 `import --input 文件 --output 预检文件`，取得规范化 `event_keys`；核对完整区间和全部版本后，再填覆盖证明与候选身份，再次预检，最后加 `--apply`。整批先验证再写入，相同内容重复导入保留首次观测；候选迁移不会改变原分红方案的可见时间。审计遇到 qfq/unknown 存量时保留原数据，需另行重新采集原价，禁止反推或覆盖。

盘后通达信增量及独立 CLI 在解析日历时同时拆解官方 GBBQ 归档，按归档 SHA256 打检查点；失败重试不会重复事件，也不会生成覆盖证明。分红同步会同步维护候选，已有方案未变化时也能补恢复上次失败的候选写入。两者继续需要公开实施公告补齐和覆盖核验，不能把“候选同步成功”解释为“策略数据已可信”。
