# 公司行为与复权

平台以不复权日线保存真实成交，以独立事件记录生成研究价格，以权益账本处理实际现金和股数。不能用一条复权价格曲线代替组合账本。

## 当前数据源原则

现阶段以通达信长期提供的免费、公开数据建设日 K 级量化研究平台。通达信是行情和价格调整事件的主来源，采用其口径作为本平台基准；只有所需数据在通达信中不存在时，才考虑其他公开来源补充。补充字段须记录来源、单位、适用日期及用途，不能无提示地覆盖通达信已有数据。

不要求不同平台的数据严格一致，也不将跨平台逐项比对或全部公告人工核验作为普通价格研究的普遍前置条件。可容忍来源口径、数值精度及舍入造成的有限误差，并保留来源与计算身份。错误单位、送转/拆合股倍数、重复事件、错误生效日期、未来信息泄漏、显著异常复权跳变及现金或股份重复记账可能实质影响策略，仍须校验、隔离或中止受影响范围。跨源差异本身不自动判定通达信错误，不能使用统一误差百分比掩盖这些语义问题。

价格连续性与实际权益到账分别判断。研究复权不应因缺少与价格变换无关的派息日、股份上市日而一律阻断；涉及账户可用现金、可卖股数或配股认购时，必须明确相关事实与处理规则。价格能力和权益能力已分别接入；运行时按下述来源、覆盖区间和异常范围检查，不要求为普通价格研究逐条制作公告证明。

## 当前数据范围

存量来源明确且口径为 `none` 的通达信和公开补充日线继续保留，没有重写或清空价格大表。当前研究覆盖查看价格发布中的起止日期及异常，实际权益查看对应补齐检查；旧 qfq/unknown 行情仍不能反推原价。旧回测和策略源码不自动重算或改写。

通达信公开 `gbbq.zip` 中的 `gbbq` 文件现在能够解码；归档同时还包含交易日历。候选保留证券、供应商事件日、类别、Float32 原值的可往返十进制表示、原始文件 SHA256、首次观测时间和内容身份。解析严格验证记录数量、长度、ZIP 成员及数值；不解压或执行归档中的程序。非流通上市、增发、回购等不会直接转换为价格复权事件；未知类别保留待核对。

GBBQ 不提供完整的公告版本、登记日、现金到账日及股份上市日。平台从完整归档生成 `tdx-price-adjustments`：它描述通达信口径的历史价格调整能力，并明确标记 `historical-effective-date-reconstruction`。它不是原始公告版本库，不能据此研究公告发布前后的信息优势，也不声称严格恢复所有历史修订的 PIT。

类别 1 按每十股现金、配股价、每十股送转、每十股配股转换，现金和比例保留源 Float32 精度。类别 11 按供应商缩股比例生成价格调整，但不把总股本缩减直接当作个人账户股数。类别 12 是非流通股缩股，不直接调整股票成交价；类别 2 的送配股上市日只用于补充实际股份可卖日期的交叉佐证。股本、增发、回购等非价格记录不套用除权公式。类别 13/14 的权证不作为普通股票价格事件，持仓涉及该日时要求专用权益处理。类别 4/15、同日冲突、无效数值等保留为有日期的 `issues`，隔离跨越该日的研究窗口，不将全市场判为不可用。

发布覆盖从已存原价首日到归档内 `gbbq` 的日期，不因隔天重新导入旧文件而延长。无事件证券的覆盖依据是完整通达信归档清单，不能由其他接口的空响应替代。保留来源、归档 SHA256、转换版本、前收盘上下文和内容身份；已有来源明确的少量原价补充可以参与上下文，但不覆盖通达信已有行情。缺原价、未知口径或缺少通达信上下文的证券不发布。当前发布与历史内容版本分别保存在已有通用记录表，无新增外键。

公开巨潮实施分红资料仅补充缺少的实际现金、公告、登记和到账字段，按证券及除权日唯一匹配并绑定通达信经济条款身份；送转比例必须相符，实际现金可以与差异化除权现金不同。股份到账日还须与通达信类别 2 的上市日一致。缺字段、配股、重整或无法判断的拆合股规则不会自动生成权益。接口采集失败或空响应不会解除检查，也不会改变研究价格。平台未接入付费数据源。

普通价格研究不依赖完整权益日期；持仓在事件日缺少必要权益时，回测与实盘明确中止。已知有价格异常且未持仓的证券可从当次候选集排除，回测与实盘结果记录排除原因；显式查询、下信号或已有持仓不能绕过。Mock 不解除这些检查。旧回测、锁定策略和原价存储不自动重算或改写。

## 数值和时点

同一证券、同一除权日的现金、送转、配股等须合并成一个事件。`cash_per_share` 为税前人民币元/原股；`share_multiplier` 为送股、转增、拆合股后的非配股股数/原股，正常为 1，拆股大于 1、合股小于 1；`rights_ratio` 为每原股可配股数，`rights_price` 为配股价。普通参考价为：

```text
reference = (previous_close - cash_per_share + rights_ratio * rights_price)
            / (share_multiplier + rights_ratio)
price_ratio = reference / previous_close
```

交易所批准特殊算法时，可提供公告明确的 `reference_price`；仍须完整说明经济权益。参考价必须为正；事件前收盘价与已读取原价不一致时中止。增发、回购、可转债转股、单纯流通股变化不能仅凭股本数量套用该公式。

事件的 `available_at` 是该**具体版本**可获知的时间，必须带时区；`observed_at` 是本平台观测时间。补充源仅有公告日期时，历史版本按公告日结束重建并标明依据；观测当天的公告使用实际采集时点。没有公告日期不生成权益。修订追加内容寻址版本，不覆盖旧记录；同一公告时间出现不同内容、登记后权益发生修订均报冲突。公司行为及覆盖存于已有 `market_records`，无新外键、无价格大表迁移。

手工核验通道仍可使用标准覆盖证明，独立保存 `start_day/end_day`、公开证据、区间内全部事件版本的 `event_keys`、已核对候选的 `resolved_candidate_keys`。它是数据审计元数据，不作为策略经济信息；不能认证尚未发生的未来日期。新事件版本或新候选不在既有核验内时会重新阻断。取消方案或不构成除权的候选，须在 `candidate_resolutions` 中给出 `dismissed:公开证据及说明`，不能为清除阻断伪造实施事件。

## 研究接口

```python
bars = context.history("000001")                    # 默认 qfq
actual = context.history("000001", adjustment="raw")
backward = context.history("000001", adjustment="hfq")
events = context.corporate_actions("000001", since="2026-01-01")
today = context.trading_day()                       # 不触发历史行情读取
```

`history` 为 DataFrame / float64。`qfq` 以当前决策日为锚，将此前已生效事件的 `price_ratio` 累乘到早期 OHLC；`hfq` 以本次窗口首日为基准，对后续 OHLC 乘逆比例。元数据标明 `price_basis`、`adjustment_anchor`、`price_scale`。未来除权不提前生效。通达信价格发布按生效日重建，严格事件通道仍按具体公告版本过滤；两者的历史能力不能混称。子进程只收到决策时点已知的经济版本，完整审计保留在宿主及回测结果。

`raw_open/high/low/close` 保留对应原价；`volume/amount` 保留实际成交股数/元。`adjusted_volume` 仅按股数变化换算（现金分红不会改变它），`adjusted_vwap` 将实际成交额/实际成交量换算到与研究 OHLC 相同的价格尺度。Alpha101 的量和 VWAP、成交量变化回归使用这些派生列；成交额因子保持实际金额。指数不进行股票公司行为复权。

`context.library('market.daily-bars', ...)` 与技术因子采用相同研究视图。成交、`current_price/quotes`、资金及股数账本继续使用真实原价和 Decimal。`context.data['prices'/'bars']` 是兼容的原始输入，不应直接用于跨除权收益或技术因子；新代码使用 `history/library/factor`。

`corporate_actions` 返回已生效的价格事件（可用 `since` 限定保存价格锚之后的事件）的 `event_id`、`record_key`、`ex_date`、`price_ratio`、`share_multiplier`、`cash_per_share`。这些现金和股数分量用于价格换算，不等于账户实际应收；策略保存的价格阈值应按事件幂等调整，不能因每个 hook 重复变换。网格模板会调整其价格锚，并在已处理事件发生修订时要求复核；已有锁定策略须复制草稿自行适配，平台不修改其 KV 或源码。

乘法前后复权收益在同一基准下可比较，**不等于**实际账户现金分红到账后再投资的收益。平台不会自动将分红再投资，也不把税前回测口径冒充个人税后到账。

曲线中的临时股票比较按每个观察时点的已知事件复权，并将起点换算到相同价格基准；现金分红不会产生虚假的价格跌幅。它仍是复权价格收益比较，不是账户税后再投资收益。

日线 API 可显式查询 `?adjustment=qfq|hfq|raw&as_of=带时区ISO时间`；带 `as_of` 的研究请求执行同样校验。默认无参数的 raw 查询保留事实浏览兼容性。股票 K 线页面默认前复权，提供不复权和后复权 Tab；指数保持原口径。页面普通查询锚定最后可见日线，显式 `as_of` 则按指定决策时点校验。先调整日线再聚合周/月线，模式进入缓存键，失败展示错误和重试，不静默换成原价。

## 回测与实盘权益

回测在登记日收盘锁定权益；除权日确认应收现金及股份，现金到派息日才可用，新增股份到上市日才可卖。拆合股替换股份在上市前锁定。卖出登记日已有股票不丢失已登记分红；除权日新买入不追溯获得分红。停牌期间保留最后价格，并按已知公司行为变换估值基准（参考价继续使用通达信价格口径，实际应收使用补充源金额），避免资产因缺当日 K 线消失。结果保存事件快照、SHA256、组合输入身份及登记/除权/到账/上市流水；股票收益归因包含分红和股份变化。

当前回测现金分红采用税前金额及分币四舍五入，不模拟持有期差异化红利税。持仓配股缺少明确认购/缴款/权益处置模型时中止；产生碎股、缺登记日持仓快照或登记后修订时也中止。价格参考公式支持配股不代表账户已认购，不会凭空增加股份或忽略认购成本。这些场景尚未全自动支持。

实盘按人工已确认操作重建真实账本。实例详情提供按需加载的“公司行为核对”，展示登记数量、税前应得现金、股份增减及到账日期；全部到账后填写实际净现金与不含账号的凭证说明。确认按事件版本幂等记账、保留审计、维持股份变动前后的总成本，并使除权前未处理建议失效。未核对前停止生成建议；未知覆盖、待核对及修订冲突期间不展示可验证收益。公司行为入账不是外部追加资金，也不伪装成买卖成交标记。配股和碎股不能通过这个通用表单跳过核实。

## 一次性整理与持续同步

所有命令均从仓库根运行，默认预览，只有 `--apply` 写入。输出真实资料应放在已忽略的 `backend/.local-data/`，不要提交凭证。

`import-gbbq` 省略 `--symbol` 时一次处理归档内所有受支持股票，指定该参数才过滤单股，无需逐股循环。`audit` 和 `migrate-dividends` 当前要求至少一个 `--symbol`。解码由导入器完成，无需手工解密。`--apply` 只写入候选，不会自动增加研究复权事件或覆盖证明，报告中的 `trusted_events_added: 0` 不表示导入失败。

```powershell
# 全市场候选导入：省略 --symbol，先预览，再明确写入
pnpm data:corporate-actions import-gbbq --input backend/.local-data/tdx/daily/gbbq.zip --output backend/.local-data/gbbq-all-preview.json
pnpm data:corporate-actions import-gbbq --input backend/.local-data/tdx/daily/gbbq.zip --apply --output backend/.local-data/gbbq-all-import.json
# 下列 --symbol 示例用于单股筛选、审计和旧分红方案整理
pnpm data:corporate-actions audit --symbol 000001 --output backend/.local-data/actions-audit.json
pnpm data:corporate-actions import-gbbq --input backend/.local-data/tdx/daily/gbbq.zip --symbol 000001 --output backend/.local-data/gbbq-preview.json
pnpm data:corporate-actions migrate-dividends --symbol 000001 --output backend/.local-data/dividend-preview.json
# 核对候选后，才明确写入候选；不会新增可信事件、覆盖或改写任何 K 线
pnpm data:corporate-actions import-gbbq --input backend/.local-data/tdx/daily/gbbq.zip --symbol 000001 --apply --output backend/.local-data/gbbq-import.json
```

标准事件文件采用 `schema_version: corporate-actions-v1`，顶层包含 `source`、`evidence`、`events`、`coverage`。事件字段为上文数值，加上 `symbol`、`event_id`（`证券代码:除权日`）、`ex_date`、`record_date`、`available_at`、`status`（implemented/cancelled）、`kinds`、`cash_pay_date`、`shares_listing_date`、`evidence`；可选特殊 `reference_price`。`kinds` 允许 cash_dividend、bonus、capitalization、rights、split、consolidation。缺字段拒绝写入，不猜测日期。

先对 `coverage: []` 的文件运行 `import --input 文件 --output 预检文件`，取得规范化 `event_keys`；核对完整区间和全部版本后，再填覆盖证明与候选身份，再次预检，最后加 `--apply`。整批先验证再写入，相同内容重复导入保留首次观测；候选迁移不会改变原分红方案的可见时间。审计遇到 qfq/unknown 存量时保留原数据，需另行重新采集原价，禁止反推或覆盖。

完成 `import-gbbq` 只代表候选已入库。接通研究价格执行下列全市场整理，省略 `--symbol` 即可；本次实施已使用用户的 `.tmp/gbbq.zip` 完成，报告在被忽略的 `backend/.local-data/`。其他环境运行一次：

```powershell
pnpm data:corporate-actions prepare-tdx --input .tmp/gbbq.zip --output backend/.local-data/tdx-price-preview.json
pnpm data:corporate-actions prepare-tdx --input .tmp/gbbq.zip --apply --output backend/.local-data/tdx-price-applied.json
pnpm data:corporate-actions audit --symbol 000001 --output backend/.local-data/actions-audit.json
```

报告区分 `ready/reused/partial/no_raw_history/not_tdx_raw`，列出价格事件、问题日期和原因。`audit` 同时返回当前价格发布、权益补齐检查和原始事件；股票详情的数据记录中也可查看价格发布和权益检查。价格整理不修改日线，重跑按源经济条款及转换版本幂等；源修订重建，旧内容版本保留。首次只读取事件前一条原价及首末上下文，手工重跑可复用条款未变化的结果；盘后自动任务每次重读这些稀疏上下文，以覆盖原价修订后的恢复，不扫描全部历史 K 线。原价历史修复后用 `--force-rebuild` 重读上下文；增量 CLI 的 `--replay` 会同时强制重建。

`prepare-tdx --apply` 自动排入 `tdx-equity-enrichment` 后台任务。按股票分段、5 秒间隔续传，公开请求在隔离子进程内执行，25 秒超时终止；单股失败重试三次后记录失败并继续。已有未完成任务时复用，避免每日堆积。近期事件每日复查、历史缺口每七日复查、已完成历史每九十日复查；经济条款变化立即重新匹配。完成状态为 partial 时查看 failed 和 unresolved，不意味着所有权益已经补齐。只需正常运行新版 worker，不需要管理员每日下载或导入。

“通达信 A 股盘后增量”及独立 CLI 自动下载官方 GBBQ、保存内容寻址归档、解析候选，在行情更新后转换并发布价格数据，再调度公开权益补齐。价格发布整批事务提交；失败保留上一批，不出现半市场更新，覆盖不会因空响应前进。公开权益补齐失败不影响已发布的价格能力。首次更新应用代码后重启 API 和 worker；保持现有盘后定时任务运行。使用全量历史包重建原价后，应重新运行一次 `prepare-tdx --force-rebuild --apply`。
