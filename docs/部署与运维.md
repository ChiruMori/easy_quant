# 部署与运维

策略公共库升级后重启 API 和 worker；上下文 KV 复用现有实盘持久文档，无新增迁移。`EASY_QUANT_INTRADAY_RUN_TIME=14:50` 统一盘中触发时刻，worker 会迁移已有间隔计划；实盘默认不启用盘后阶段。`EASY_QUANT_DAILY_DATA_PUBLISH_TIME=22:00` 控制新鲜度判定，在定时任务页面另建“盘后全量数据同步”的每日 cron（`0 22 * * *`），保持两者时间一致。子任务的失败详情在数据获取页查看，可按相同范围重新创建获取任务。

## 本地开发

后端环境固定为 `backend/.venv`，前端使用 pnpm。先准备 MariaDB，复制 `backend/.env.example` 为 `backend/.env`，填写 `EASY_QUANT_DATABASE_URL`，并运行一次 `pnpm migrate` 初始化全新数据库。之后运行 `pnpm dev` 同时启动 Flask、Vite 和单 worker；worker 执行数据同步、策略快速测试、回测和定时任务。单独排障可运行 `pnpm dev:worker`，但不要与已有 worker 并行启动。VS Code 应选择“全栈开发（含 Worker）”；仅运行双端热更新时，后台任务会持续停留在排队状态。

开发、测试部署和生产运行时均连接所配置的 MariaDB，数据库不可用或配置缺失时后端直接启动失败，不会回退到内存。Alembic 包含冻结的 `0001_initial` 基线、`0002_history_metadata` 元数据及检查点迁移和 `0003_history_coverage_index` 覆盖统计索引迁移；旧记录来源及口径标记为 `unknown`。在大型已有行情库建立索引需要扫描历史，升级前应预留维护时间和磁盘空间。首次启动自动创建配置中的管理员，必须先修改示例密码与密钥。

## 单机容器

复制 `deploy/.env.example` 为 `deploy/.env`，设置数据库密码、应用密钥、凭据加密密钥和初始管理员密码，在 `deploy` 目录执行 `docker compose up --build -d`。编排会先运行 Alembic，再启动单 worker API、worker 和 Nginx。默认 Web 端口为 `8080`。

ntfy 默认使用 `https://ntfy.sh`，可用 `EASY_QUANT_NTFY_BASE_URL` 指向自建服务。邮件需要配置 SMTP 主机、端口、发件人及可选账号密码。生产 HTTPS 环境应设置 `EASY_QUANT_SESSION_COOKIE_SECURE=true`。

## 运维命令

- `pnpm migrate` 或 `tools/migrate.ps1`：升级数据库。
- `pnpm data:tdx download|inspect|import`：下载、预检及导入通达信全量 A 股日线，详细见[操作说明](通达信历史数据.md)。
- `pnpm data:tdx:update`：下载官方单日增量、补齐缺日并写入不复权日线；`0004_tdx_daily_checkpoints` 迁移创建日期检查点。升级后重启 API/worker；在“定时任务”创建“通达信 A 股盘后增量”计划即可按 Cron 执行。
- `0005_large_run_payloads` 扩大任务结果、回测详情和策略源码字段容量；回测快照压缩内容按数据库 BLOB 限额分块。升级本版本前先执行 `pnpm migrate`，再重启 API 和 worker。
- `0006_job_identifier_length` 将 `jobs.id` 扩至 64 字符，容纳 `job-` 前缀 UUID；修复策略快测、回测和手动同步入队时的 MariaDB 1406 错误。已有数据库须先执行 `pnpm migrate`，再重启 API 和 worker。
- `0007_daily_bar_day_index` 为全市场日线增加交易日优先索引，使快测的所选日及此前最多 5 个交易日窗口与按日期查询不再扫描全史。已有 1,800 万行日线表建索引可能耗时并影响写入，请选择维护时段运行 `pnpm migrate`，完成后重启 API 和 worker。worker 启动、领取、完成及失败会在控制台记录任务标识和类型，不打印任务载荷。
- `0008_runtime_bar_covering_index` 的旧实现曾尝试创建 7 列宽索引，已撤销；该修订号现保留为空操作，以兼容中断迁移。`0009_repair_runtime_indexes` 会保留原有日期索引和覆盖统计索引，仅在发现错误的宽索引时删除；若有环境已完成旧版 `0008` 而失去日期索引，`0009` 会先重建窄日期索引。见下方状态检查和维护步骤。
- `0010_expand_raw_cache_blob` 将原始响应缓存的 `payload_gzip` 从 BLOB 扩为 LONGBLOB，修复完整证券清单约 208 KB 的压缩响应写入失败。升级代码后先运行 `pnpm migrate`，再重启 API 和 worker，之后重新发起“证券列表”完整刷新。若当前数据库尚未完成 `0009`，本次迁移会先执行该索引修复，请按下方维护步骤确认其影响。缓存写入或其他任务处理失败时，worker 会先回滚会话再记录失败状态；数据库异常日志会隐藏绑定参数。
- `tools/health.ps1 [-RequireWorker]`：检查 API 和 worker。
- `tools/backup.ps1 -Path <file>`：备份；恢复会覆盖数据库，必须人工确认目标。
- `pnpm fix`：格式化并自动修复前后端代码。
- `pnpm check`：运行格式、静态检查、单元测试和前端构建。

日志会脱敏密码、令牌、密钥、邀请码和联系方式。国际网络代理只用于开发时手动访问，不是应用和测试依赖。

## 大表索引维护与性能验收

迁移前备份数据库，选择停写或低负载维护窗口，检查磁盘剩余空间、`SHOW INDEX FROM daily_bars`、`SELECT version_num FROM alembic_version`、`information_schema.TABLES` 的表与索引大小，以及 MariaDB 当前 `innodb_buffer_pool_size`。2026-10-04 中断迁移后的开发库仍为 `0007`，三条二级索引同时存在：旧日期索引、窄覆盖统计索引和已建成的 7 列宽索引。约 1818 万行，数据约 3.3 GiB，总索引约 1.78 GiB（建宽索引前约 0.58 GiB），缓冲池仅 128 MiB。不要用旧版 `0008` 再次迁移。先部署包含 `0009` 的代码，再按下述流程处理。应用不依赖 Redis。

确认备份后停 API、worker 与同步任务，排查长事务和 `SHOW PROCESSLIST` 中等待元数据锁的会话。在维护窗口执行新版 `pnpm migrate`：当前 `0007` 且旧日期索引仍在时，不再建任何索引，仅删除宽索引；若旧版 `0008` 已完成且旧日期索引缺失，恢复窄索引会再次扫描大表，应预留更长窗口。`DROP INDEX` 通常是 InnoDB 元数据操作，但仍可能等待其他会话的元数据锁，不能保证瞬时完成。迁移后确认版本为 `0009`、宽索引已消失、日期和覆盖索引仍在；再启动服务。删索引后 InnoDB 表空间文件不保证立即缩小，不能为了立即回收操作系统空间而擅自运行 `OPTIMIZE TABLE` 或重建这张大表。若迁移卡住，先读 `SHOW PROCESSLIST` 查锁等待，不要盲目重复执行。回退代码版本必须匹配索引结构，`0009` 的 downgrade 不会重新创建错误的宽索引。

主键批量读取六日 33,282 行，在现有 128 MiB 缓冲池下只读复测约 6.6–7.4 秒；这只是数据库取数耗时，尚未达到快测全链路 5 秒目标。不要据此声称多年回测和盘中目标已达成；结合机器内存、数据库负载评估缓冲池，观察命中率、冷/热读取和 worker 阶段计时后再验收。`ix_daily_bars_coverage` 与主键键列相同，但叶页只存键，约占 279 MiB。实际数据管理页一页 50 只股票的精确 `MIN/MAX/COUNT`（共 349,965 条日线）重复计时，二级索引 0.19/0.19 秒、主键 3.65/3.46 秒；这是同一覆盖统计查询的对照，**不是** OHLC 读取对照。状态筛选也依赖全市场覆盖统计。直接删除该索引会让这些路径扫描更宽的聚簇记录；若要节省这部分空间，应先设计并验证事务内维护的覆盖摘要，再删除索引，不能仅凭键列重叠判为无效。

`ix_daily_bars_day_symbol` 约占 314 MiB，当前仅在短时间窗口先查 `DISTINCT symbol` 时发挥索引覆盖作用；从它直接读取价格会逐行访问聚簇记录，实际行情读取已改为按股票主键范围。只读同投影对照中，2026-09-01 至 09-06 的 22,190 条 OHLC 行，日期索引直接读耗时 18.69 秒，日期索引找代码加主键批量读耗时 0.18 + 6.10 秒，排序后结果相同。按月样本，2005/2010/2020/2026 年有行情股票分别为 1,349/1,692/3,765/5,571 只，而当前股票元数据有 6,157 只；用整张股票表代替代码发现会在早期回测产生大量无效主键范围。单列 `trading_day` 的二级索引也会携带主键 `symbol`，重建成单列形式没有明确空间收益。两条窄索引均有独立且实际使用的读取路径，本次不增删它们；后续若引入可靠的覆盖摘要及按日期的代码集合，再用同结果集、同列投影的查询和写入成本复测，决定是否删除。

快测 worker 日志报告读数、上下文、子进程耗时和行数/缓存命中；回测报告策略阶段与快照保存耗时。运行时只用窄日期索引确定区间内股票，再按股票分批走聚簇主键范围读取所需字段；回测按月分块，不将多年 OHLC 一次性载入内存。快照短区间也按主键批量读取，较长区间顺序扫描聚簇主键，以临时文件和分块 gzip 保存。运行机器的临时目录需有足够空间；失败时检查数据库执行计划、缓冲池压力、临时磁盘空间及 worker 日志，再决定是否需要后续规格，不应直接分表。

任务表的 `available_at` 等 DATETIME 原始值统一按 UTC 存储。例如数据库中的 `2026-10-03 11:23:32` 对应北京时间 `2026-10-03 19:23:32`，不是延后或提前 8 小时的调度错误。API 返回带 `+00:00` 的 ISO 时间，后台任务页固定转换为北京时间显示；排障时不要手工给数据库值加 8 小时。

## 浏览器验收

运行 `pnpm test:e2e` 会通过 uv 和 pnpm 启动专用 Flask `5100` 与 Vite `5174`，不依赖 PowerShell。测试使用显式注入的 fake 容器，不连接 `backend/.env` 中的真实数据库。需安装 Google Chrome，并确保这两个测试端口空闲；日常开发使用的 `5000` 与 `5173` 可同时运行。
