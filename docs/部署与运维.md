# 部署与运维

## 本地开发

后端环境固定为 `backend/.venv`，前端使用 pnpm。先准备 MariaDB，复制 `backend/.env.example` 为 `backend/.env`，填写 `EASY_QUANT_DATABASE_URL`，并运行一次 `pnpm migrate` 初始化全新数据库。之后运行 `pnpm dev` 同时启动 Flask、Vite 和单 worker；worker 执行数据同步、策略快速测试、回测和定时任务。单独排障可运行 `pnpm dev:worker`，但不要与已有 worker 并行启动。VS Code 应选择“全栈开发（含 Worker）”；仅运行双端热更新时，后台任务会持续停留在排队状态。

开发、测试部署和生产运行时均连接所配置的 MariaDB，数据库不可用或配置缺失时后端直接启动失败，不会回退到内存。Alembic 包含冻结的 `0001_initial` 基线、`0002_history_metadata` 元数据及检查点迁移和 `0003_history_coverage_index` 覆盖统计索引迁移；旧记录来源及口径标记为 `unknown`。在大型已有行情库建立索引需要扫描历史，升级前应预留维护时间和磁盘空间。首次启动自动创建配置中的管理员，必须先修改示例密码与密钥。

## 单机容器

复制 `deploy/.env.example` 为 `deploy/.env`，设置数据库密码、应用密钥、凭据加密密钥和初始管理员密码，在 `deploy` 目录执行 `docker compose up --build -d`。编排会先运行 Alembic，再启动单 worker API、worker 和 Nginx。默认 Web 端口为 `8080`。

ntfy 默认使用 `https://ntfy.sh`，可用 `EASY_QUANT_NTFY_BASE_URL` 指向自建服务。邮件需要配置 SMTP 主机、端口、发件人及可选账号密码。生产 HTTPS 环境应设置 `EASY_QUANT_SESSION_COOKIE_SECURE=true`。

## 运维命令

- `pnpm migrate` 或 `tools/migrate.ps1`：升级数据库。
- `pnpm data:tdx download|inspect|import`：下载、预检及导入通达信全量 A 股日线，详细见[操作说明](通达信历史数据.md)。
- `pnpm data:tdx:update`：下载官方单日增量、补齐缺日并写入不复权日线；`0004_tdx_daily_checkpoints` 迁移创建日期检查点。升级后重启 API/worker；在“定时任务”创建“通达信 A 股盘后增量”计划即可按 Cron 执行。
- `0005_large_run_payloads` 扩大任务结果、回测详情和策略源码字段容量；回测快照压缩内容按数据库 BLOB 限额分块。升级本版本前先执行 `pnpm migrate`，再重启 API 和 worker。
- `0006_job_identifier_length` 将 `jobs.id` 扩至 64 字符，容纳 `job-` 前缀 UUID；修复策略快测、回测和手动同步入队时的 MariaDB 1406 错误。已有数据库须先执行 `pnpm migrate`，再重启 API 和 worker。
- `0007_daily_bar_day_index` 为全市场日线增加交易日优先索引，使快测的所选日及此前最多 5 个交易日窗口与按日期查询不再扫描全史。已有 1,800 万行日线表建索引可能耗时并影响写入，请选择维护时段运行 `pnpm migrate`，完成后重启 API 和 worker。worker 启动、领取、完成及失败会在控制台记录任务标识和类型，不打印任务载荷。
- `0008_runtime_bar_covering_index` 用 `(trading_day,symbol,available_at,open,high,low,close)` 覆盖策略运行的 OHLC 读取，建好后替换旧日期索引；保留 `ix_daily_bars_coverage` 供覆盖率聚合。18M 行表的建索引和删索引属于大表 DDL，不应在业务繁忙时直接运行，见下方维护步骤。
- `tools/health.ps1 [-RequireWorker]`：检查 API 和 worker。
- `tools/backup.ps1 -Path <file>`：备份；恢复会覆盖数据库，必须人工确认目标。
- `pnpm fix`：格式化并自动修复前后端代码。
- `pnpm check`：运行格式、静态检查、单元测试和前端构建。

日志会脱敏密码、令牌、密钥、邀请码和联系方式。国际网络代理只用于开发时手动访问，不是应用和测试依赖。

## 大表索引维护与性能验收

迁移前备份数据库，选择停写或低负载维护窗口，检查磁盘剩余空间、`SHOW INDEX FROM daily_bars`、`information_schema.TABLES` 的表与索引大小，以及 MariaDB 当前 `innodb_buffer_pool_size`。当前开发库约 1818 万行、数据约 3.3 GiB、索引约 0.6 GiB，但缓冲池仅 128 MiB，冷读易被磁盘 I/O 主导。覆盖索引增加存储和导入维护成本；应结合主机内存及其他服务负载，将缓冲池调整到能容纳常用工作集的范围，再观察命中率和内存压力，不盲目照搬固定值。应用不依赖 Redis。

确认备份与剩余空间后，停用同步任务，在维护窗口执行 `pnpm migrate`。迁移先创建新索引再删除旧索引；若建索引失败，旧索引仍在，不要未经检查重跑。完成后对代表性六日查询运行 `EXPLAIN`，确认选择 `ix_daily_bars_runtime_day` 且为 `Using index`；检查 `alembic_version` 和 worker 日志。回退先停 worker，再执行 `uv run --project backend alembic -c backend/alembic.ini downgrade 0007_daily_bar_day_index`，它会重建旧索引后删除新索引，同样需维护窗口和磁盘空间。回退代码版本也必须匹配旧索引，不能只回退数据库。快测预热后 5 秒、盘中分析 2 分钟、多年回测 10–30 分钟是验收目标，并非未迁移时的实测结论。

快测 worker 日志报告读数、上下文、子进程耗时和行数/缓存命中；回测报告策略阶段与快照保存耗时。回测逐日读取运行列并保持受限策略子进程；快照读取完整来源字段，30 日以内用日期索引，较长区间顺序扫描聚簇主键，以临时文件和分块 gzip 保存，避免将多年历史一次性载入内存。运行机器的临时目录需有足够空间；失败时检查数据库执行计划、缓冲池压力、临时磁盘空间及 worker 日志，再决定是否需要后续规格，不应直接分表。

任务表的 `available_at` 等 DATETIME 原始值统一按 UTC 存储。例如数据库中的 `2026-10-03 11:23:32` 对应北京时间 `2026-10-03 19:23:32`，不是延后或提前 8 小时的调度错误。API 返回带 `+00:00` 的 ISO 时间，后台任务页固定转换为北京时间显示；排障时不要手工给数据库值加 8 小时。

## 浏览器验收

运行 `pnpm test:e2e` 会通过 uv 和 pnpm 启动专用 Flask `5100` 与 Vite `5174`，不依赖 PowerShell。测试使用显式注入的 fake 容器，不连接 `backend/.env` 中的真实数据库。需安装 Google Chrome，并确保这两个测试端口空闲；日常开发使用的 `5000` 与 `5173` 可同时运行。
