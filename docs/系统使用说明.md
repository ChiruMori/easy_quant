# 系统使用说明

## 1. 首次登录与邀请用户

部署者在 `backend/.env` 或容器环境中设置 `EASY_QUANT_INITIAL_ADMIN_USERNAME` 和 `EASY_QUANT_INITIAL_ADMIN_PASSWORD`。首次启动会自动创建管理员。打开网页登录后，可从左侧导航底部退出登录。

管理员进入“系统管理 → 邀请码”，创建一次性邀请码并将邀请码单独交给受邀用户。受邀用户在登录页选择“使用邀请码注册”，设置用户名和密码后登录。系统不开放无邀请码注册，也不提供密码找回。

## 工作台导航与概览

工作台采用蓝色主操作、浅灰背景和卡片式数据布局。左侧“研究空间”包含概览、策略、因子、回测和实盘；管理员另外可见“平台管理”。当前页面对应的导航项会高亮，顶部显示当前位置。窄屏通过“切换导航”打开菜单，选择页面后菜单自动收起，也可使用右上角关闭按钮返回原页面。账户名与退出登录分行显示，较长名称可通过悬停查看。

“研究概览”展示当前账户可访问的策略数、回测记录数、运行中的实盘数，以及最多 5 条回测记录。统计来自已有业务列表，不合并不同策略的收益；加载中显示占位，读取失败显示错误并支持“重新加载”。空数据会说明如何开始研究。

桌面通过侧栏品牌右侧的“收起侧栏”按钮折叠导航。收起后悬停顶部品牌图标会显示展开图标和“展开”提示，点击恢复；键盘 Tab 聚焦后也可用 Enter/Space 操作，Ctrl/Cmd+B 可快速切换。

“回测研究”展示全部、已完成和等待/运行中的记录数；详情将指标、组合权益、运行耗时和交易披露分区展示。权益图以元为单位，蓝色表示权益曲线；收益指标沿用红涨绿跌，任务状态以文字和独立状态标签区分。缺失指标显示“—”。宽表格可在自身区域横向滚动。

## 2. 准备数据

管理员先进入“数据管理 → 运行拉取”，依次刷新交易日历和全部股票信息，再按股票代码与日期范围同步日线。估值与市值、质押率和财务指标也可在同一表单中同步。

“股票数据覆盖”表按每页 50 只股票加载，可按名称、代码搜索并按同步状态筛选。点击股票进入详情，可按日期查看已有日线 K 线。“股票数据覆盖”表说明：

- 发布时刻（默认 22:00）前以最近已发布交易日判断新鲜度，此后以当天为目标。
- “已过时”表示已有至少三个月历史数据，但缺少最近交易日。
- 已过时行可更新到推荐日期；来源尚未发布目标日期时隐藏无效更新按钮。
- 补齐日线会自动沿用该股票已有的不复权或前复权口径；无历史数据时默认前复权。
- 点击“更新至”后，列表持续显示任务进度、完成结果或来源失败明细。东方财富来源不可达时还会尝试独立的腾讯行情来源；如果股票停牌，系统会说明来源的最后 K 线日期，不会补造行情。
- 核实交易所公告后，可在股票详情填写状态依据并标记“已停牌”；停牌股票不显示过期与更新按钮。复牌后从详情恢复交易状态。
- “已退市”表示股票已不在最近一次完整证券清单中；历史数据仍可查看，但不显示更新标签或补齐按钮，也不参与新的快速测试、回测和实盘分析。

管理员可在“系统管理 → 定时任务”创建“盘后综合数据同步”任务，使用每天 22:00 的 cron。任务同步当日日线及基础数据，并为分批获取创建可查询的子任务；盘前只读取已同步数据。
点击手动同步后，页面立即显示已创建的任务编号和排队状态；worker 执行后会更新成功或失败及来源尝试。系统管理的“后台任务”每 5 秒刷新一次；运行任务租约过期时会提示检查 worker，worker 重启后可重新领取。开发时 `pnpm dev` 会同时启动 API、前端和 worker，单独运行则需 `pnpm dev:worker`。

如需导入文件，日线 CSV 使用 `symbol,trading_day,open,high,low,close,volume`；其他数据集至少使用 `symbol,available_at`。先预检，确认无错误后再导入。切换数据集或重新选择文件会清除旧预检结果；预检或导入失败时显示原因，提交失败后可重试。

## 3. 查看因子并编写策略

“因子”页面是只读目录。打开因子详情可查看参数、输出、时间语义和调用示例。因子由平台提供，策略通过 `context.factor(...)` 使用。

“策略”先打开分页版本列表，支持搜索、状态筛选及查看、编辑、删除。点击加号新建空白草稿；“代码模板”菜单包含空白与两个示例，确认后覆盖代码。编辑页右侧的公共库可搜索和展开接口，窄屏位于底部。推荐实现三个钩子：

```python
def before_market(context, parameters):
    return []


def on_market(context, parameters):
    return []


def after_market(context, parameters):
    return []
```

草稿可原地保存；首次提交回测后为“测试中”，进入实盘后为“已实盘”，状态不回退。非草稿的列表或详情编辑按钮会先提示创建新的草稿版本。快速测试先选择交易日，再点击播放图标“运行快速测试”；无需先保存代码，不创建版本、不保存历史代码快照，也不改变策略状态。系统排队执行该交易日的三个钩子，在当前页面显示各阶段信号、标准输出或错误。快测只读取该时点可见的已同步数据；缺失数据会在任务结果中显示失败原因。

## 4. 回测

进入“回测 → 创建回测”，选择策略版本和时间范围，填写初始资金、手续费和滑点。股票由策略选择，不在回测表单填写。提交后立即出现排队中的回测记录，详情页自动刷新；worker 完成后可从“回测记录”查看中文指标、权益曲线、交易、假设和数据快照标识。

回测按交易日依次运行完整区间，可跨多年。MA/RSI 按需求预热（MA5 额外读取起点前 5 个交易日）；动态历史、统计和 EMA 默认 250 日。可在源码顶层声明 `HISTORY_TRADING_DAYS = N`（1–2500）并保存草稿（锁定策略须先创建新草稿版本），快测和实盘共用此历史窗口。回测页面展示校验、预热、行情读取、当前交易日/hook、快照和保存阶段；结束后可查看各阶段和逐日 hook 耗时。覆盖不足时显示缺失标的、区间及数据管理入口。

如果提示数据缺失，按清单让管理员同步相应数据集和日期范围，再重新运行。不要绕过缺失检查。

## 5. 实盘建议、通知与实际操作

实盘详情读取失败时展示原因并提供“重新加载”；尚未生成建议时显示明确空态。

在成功回测详情中点击“开启实盘跟踪”。先在“通知设置”添加 ntfy 主题或邮件地址，并确认渠道已启用。worker 必须持续运行，才能执行盘前、盘中和盘后任务。

收到建议后：

- 实际完全按建议成交时，点击“快速确认”。
- 未执行时，点击“拒绝建议”。
- 成交方向、数量、价格或费用不同，展开“修正成交”录入实际值。

当天出现过建议时，盘后通知会提醒核对持仓。后续分析以确认或修正后的实际账本为准。

## 6. 管理与排障

“系统管理”可查看用户、邀请码、定时任务、后台任务和审计记录。数据拉取失败时，在任务结果中查看每个来源、尝试次数和失败原因。通知失败时，在“通知设置 → 最近投递”查看状态，并检查 ntfy 或 SMTP 配置。

定时任务停用后可编辑类型、计划、时区与配置；启用前会重新计算下一次时间。“立即执行”创建一次后台任务，停用时也可运行，不改变下一次定时计划。盘后综合同步手动运行默认取最近已发布交易日，配置可用 `end_day` 指定目标日期。写请求期间统一加载蒙版阻断重复操作；后台任务执行及页面轮询不会遮罩。

完整开发、容器、迁移和备份命令见《部署与运维》。本系统只辅助决策，不保证收益，也不会替用户下单。

## 同步指数与查看基准

管理员在“数据管理”页面切换到“指数”Tab。默认不勾选指数，勾选需要的指数（或全选主要指数），填写起止日期后点击“同步所选指数”。页面显示任务状态、来源明细和真实覆盖，完成后可查看指数 K 线；失败时先核对日线来源配置，再重试相同区间。无需先刷新股票清单。

回测基准填写 `000300` 或 `sh000300` 即表示沪深300；上证指数须填写 `sh000001`，六位 `000001` 仍表示股票。同步对应历史区间后重新回测，详情中的蓝色组合权益与另一条基准线有独立图例、单位及中文工具提示。指数不可交易，页面不会提供股票停复牌操作。

## 数据维护任务范围

- “指定数据集同步”（原“数据拉取”）执行配置的单个 dataset_key、symbols 和日期区间；`{"mode":"daily-update"}` 仅同步最近已发布交易日的日线。
- “盘后综合数据同步”（原“盘后全量数据同步”）刷新交易日历、证券与停复牌状态，再分批补齐股票/指数日线、估值、质押、财务和行业。它不是重新下载全部历史；与单数据集同步只有部分重叠，没有删除这些不同用途的任务或用户计划。
- “通达信 A 股盘后增量”只更新股票日线，不更新指数或基本面。
- “主要指数日线同步”独立补齐七个主要指数，复用已启用的日线来源，固定不复权。执行时取最近已发布交易日，各指数从已有末日重新核验并补齐；无历史时从十年前年初开始。可配置 `symbols`、`start_day`、`end_day` 指定主要指数和区间。失败保留已完成数据，在数据获取页查看各指数结果并重试。

升级执行 `pnpm migrate` 后，若还没有指数同步计划，会新增一个工作日 22:00、Asia/Shanghai、默认停用的计划。管理员可保持停用，每天点击“立即执行”；需要自动运行时启用。已有指数计划及其他计划不会被覆盖。API 与 worker 均须更新至本版本。

后台任务每页 20 条，按计划时间倒序，同一时刻按任务 ID 倒序，支持前后翻页和页码跳转；每 5 秒刷新当前页，加载失败可重试。接口 `GET /api/v1/admin/jobs` 返回 `{items,total,page,page_size}`，默认第一页 20 条，每页最多 100 条，越界页码定位末页。
