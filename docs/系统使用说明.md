# 系统使用说明

## 1. 首次登录与邀请用户

部署者在 `backend/.env` 或容器环境中设置 `EASY_QUANT_INITIAL_ADMIN_USERNAME` 和 `EASY_QUANT_INITIAL_ADMIN_PASSWORD`。首次启动会自动创建管理员。打开网页登录后，可从左侧导航底部退出登录。

管理员进入“系统管理 → 邀请码”，创建一次性邀请码并将邀请码单独交给受邀用户。受邀用户在登录页选择“使用邀请码注册”，设置用户名和密码后登录。系统不开放无邀请码注册，也不提供密码找回。

## 工作台导航与概览

工作台采用蓝色主操作、浅灰背景和卡片式数据布局。左侧“研究空间”包含概览、策略、因子、策略公共库、回测和实盘；管理员另外可见“平台管理”。当前页面对应的导航项会高亮，顶部显示当前位置。窄屏通过“切换导航”打开菜单，选择页面后菜单自动收起。

“研究概览”展示当前账户可访问的策略数、回测记录数、运行中的实盘数，以及最多 5 条回测记录。统计来自已有业务列表，不合并不同策略的收益；加载中显示占位，读取失败显示错误并支持“重新加载”。空数据会说明如何开始研究。

“回测研究”展示全部、已完成和等待/运行中的记录数；详情将指标、组合权益、运行耗时和交易披露分区展示。权益图以元为单位，蓝色表示权益曲线；收益指标沿用红涨绿跌，任务状态以文字和独立状态标签区分。缺失指标显示“—”。宽表格可在自身区域横向滚动。

## 2. 准备数据

管理员先进入“数据管理 → 运行拉取”，依次刷新交易日历和全部股票信息，再按股票代码与日期范围同步日线。估值与市值、质押率和财务指标也可在同一表单中同步。

“股票数据覆盖”表按每页 50 只股票加载，可按名称、代码搜索并按同步状态筛选。点击股票进入详情，可按日期查看已有日线 K 线。“股票数据覆盖”表说明：

- 发布时刻（默认 22:00）前以最近已发布交易日判断新鲜度，此后以当天为目标。
- “已过时”表示已有至少三个月历史数据，但缺少最近交易日。
- 已过时行可更新到推荐日期；来源尚未发布目标日期时隐藏无效更新按钮。
- 补齐日线会自动沿用该股票已有的不复权或前复权口径；无历史数据时默认前复权。
- 点击“更新至”后，列表持续显示任务进度、完成结果或来源失败明细。东方财富来源不可达时还会尝试独立的腾讯行情来源；如果股票停牌，系统会说明来源的最后 K 线日期，不会补造行情。
- 核实交易所公告后，可在股票详情填写状态依据并标记“已停牌”；停牌股票不显示过期与更新按钮。复牌后从详情恢复交易状态。
- “已退市”表示股票已不在最近一次完整证券清单中；历史数据仍可查看，但不显示更新标签或补齐按钮，也不参与新的快速测试、回测和实盘分析。

管理员可在“系统管理 → 定时任务”创建“盘后全量数据同步”任务，使用每天 22:00 的 cron。任务同步当日日线及基础数据，并为分批获取创建可查询的子任务；盘前只读取已同步数据。
点击手动同步后，页面立即显示已创建的任务编号和排队状态；worker 执行后会更新成功或失败及来源尝试。系统管理的“后台任务”每 5 秒刷新一次；运行任务租约过期时会提示检查 worker，worker 重启后可重新领取。开发时 `pnpm dev` 会同时启动 API、前端和 worker，单独运行则需 `pnpm dev:worker`。

如需导入文件，日线 CSV 使用 `symbol,trading_day,open,high,low,close,volume`；其他数据集至少使用 `symbol,available_at`。先预检，确认无错误后再导入。

## 3. 查看因子并编写策略

“因子”页面是只读目录。打开因子详情可查看参数、输出、时间语义和调用示例。因子由平台提供，策略通过 `context.factor(...)` 使用。

“策略”页面可选择模板或创建策略。推荐实现三个钩子：

```python
def before_market(context, parameters):
    return []


def on_market(context, parameters):
    return []


def after_market(context, parameters):
    return []
```

每次保存都会产生新版本。未保存草稿保存在当前浏览器。快速测试先选择交易日，再点击“运行当前版本”；系统排队执行该交易日的盘前、盘中和盘后三个钩子，在“最近运行”显示各阶段信号、标准输出或错误。快测只读取该时点可见的已同步数据；缺失数据会在任务结果中显示失败原因。

## 4. 回测

进入“回测 → 创建回测”，选择策略版本和时间范围，填写初始资金、手续费和滑点。股票由策略选择，不在回测表单填写。提交后立即出现排队中的回测记录，详情页自动刷新；worker 完成后可从“回测记录”查看中文指标、权益曲线、交易、假设和数据快照标识。

回测按交易日依次运行完整区间，可跨多年。MA/RSI 按需求预热（MA5 额外读取起点前 5 个交易日）；动态历史、统计和 EMA 默认 250 日。可在源码顶层声明 `HISTORY_TRADING_DAYS = N`（1–2500）并保存新版本，快测和实盘共用此历史窗口。回测页面展示校验、预热、行情读取、当前交易日/hook、快照和保存阶段；结束后可查看各阶段和逐日 hook 耗时。覆盖不足时显示缺失标的、区间及数据管理入口。

如果提示数据缺失，按清单让管理员同步相应数据集和日期范围，再重新运行。不要绕过缺失检查。

## 5. 实盘建议、通知与实际操作

在成功回测详情中点击“开启实盘跟踪”。先在“通知设置”添加 ntfy 主题或邮件地址，并确认渠道已启用。worker 必须持续运行，才能执行盘前、盘中和盘后任务。

收到建议后：

- 实际完全按建议成交时，点击“快速确认”。
- 未执行时，点击“拒绝建议”。
- 成交方向、数量、价格或费用不同，展开“修正成交”录入实际值。

当天出现过建议时，盘后通知会提醒核对持仓。后续分析以确认或修正后的实际账本为准。

## 6. 管理与排障

“系统管理”可查看用户、邀请码、定时任务、后台任务和审计记录。数据拉取失败时，在任务结果中查看每个来源、尝试次数和失败原因。通知失败时，在“通知设置 → 最近投递”查看状态，并检查 ntfy 或 SMTP 配置。

定时任务停用后可编辑类型、计划、时区与配置；启用前会重新计算下一次时间。“立即执行”创建一次后台任务，停用时也可运行，不改变下一次定时计划。盘后全量同步手动运行默认取最近已发布交易日，配置可用 `end_day` 指定目标日期。写请求期间统一加载蒙版阻断重复操作；后台任务执行及页面轮询不会遮罩。

完整开发、容器、迁移和备份命令见《部署与运维》。本系统只辅助决策，不保证收益，也不会替用户下单。

## 同步指数与查看基准

管理员可从侧栏“指数数据”进入专用页面，也可通过“数据管理 → 指数数据”或“数据拉取 → 同步指数数据”进入。默认选择沪深300，勾选需要的指数（或全选主要指数），填写起止日期后点击“同步所选指数”。页面显示任务状态、来源明细和真实覆盖，完成后可查看指数 K 线；失败时先核对日线来源配置，再重试相同区间。无需先刷新股票清单。

回测基准填写 `000300` 或 `sh000300` 即表示沪深300；上证指数须填写 `sh000001`，六位 `000001` 仍表示股票。同步对应历史区间后重新回测，详情中的蓝色组合权益与另一条基准线有独立图例、单位及中文工具提示。指数不可交易，页面不会提供股票停复牌操作。
