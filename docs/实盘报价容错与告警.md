# 实盘报价容错与告警

实时行情使用平台内置的两个独立来源：腾讯按标的报价优先，东方财富按标的报价备用。这组来源与“日线K线”数据集的来源开关独立，日线同步仍沿用原有配置；报价只获取策略请求及持仓所需的代码，不抓全市场实时列表。

实时来源固定顺序按轮尝试：腾讯第一次、东方财富第一次，若均失败，等待0.25秒，再分别进行第二次尝试；首个完整有效结果即停止。每个实时来源使用独立HTTP客户端，连接及读取等网络阶段超时为3秒，不继承环境代理。超时按网络阶段生效，不是整轮严格墙钟预算；多标的批次、DNS、缓存写入及运行环境仍影响端到端时间。一般数据同步保留原有逐来源重试和来源顺序策略。

空响应、缺少任一请求标的、格式错误、非有限或非正价格、同标的重复且价格冲突，都属于来源失败，在采集层内部触发重试和切换，不再先记为成功、到策略使用时才报错。实时请求强制取新数据，不读取旧缓存、收盘价或Mock兜底。成功响应仍保存原始采集身份。

## 来源失败的诊断

每次采集输出 `数据来源请求/成功/失败` 日志，包含 `dataset`、`source`、`attempt` 和耗时；失败原因包含异常类型及脱敏消息，例如 `ReadTimeout`、`RemoteProtocolError`、HTTP状态、响应字段或缺失价格。全部耗尽时输出来源数和尝试数，任务详情的 `details.dataset`、`details.attempts` 保存全部尝试记录。其他数据同步也具有上述日志。URL凭据、常见token/API key/password、Basic/Bearer认证值会脱敏，消息长度有界。

实盘因采集来源耗尽失败时，先写持久outbox，再通过既有 `notification-delivery` 队列投递给该实例选择的本人渠道。通知包含实盘名称、交易日、钩子、每个来源最后一次尝试的原因，全部尝试见日志及任务详情。同实例、交易日和阶段的失败告警幂等，重复执行不会重复投递。没有启用且被选中的本人渠道时，投递记录标记跳过；其他人的渠道不会被使用。

失败不会生成建议、提交策略状态或标记阶段完成。来源恢复后可重新发起同阶段分析；本次两轮来源重试耗尽后，分析任务标记失败，不自动无限重跑。渠道临时失败沿用通知任务的恢复机制；入队失败保留outbox，下次分析时恢复，且不会覆盖原采集错误。若worker退出且之后没有新任务，需要先恢复worker并重新发起分析以处理未入队outbox。

## 失效来源检查

本轮核对了报价注册和响应校验：旧实时配置只有东方财富，并未注册其他备用来源。原有AKShare实时列表函数会分页抓取全市场，见其[官方实现](https://github.com/akfamily/akshare/blob/main/akshare/stock/stock_zh_a_tx.py)，因此未作为单标的实时备用调用。

只读诊断中，腾讯指定标的接口返回有效报价，东方财富出现 `RemoteProtocolError`。已有实际日志也记录东方财富成功响应，因此当前证据支持间歇性故障，不足以判定该来源永久失效；保留为短超时备用，不把它作为唯一入口。没有继续注册已知不支持实时数据集的适配器，也不把一次连接失败永久拉黑。后续日志若证实接口被固定移除或协议永久不兼容，应在平台代码中修复或移除对应绑定。
