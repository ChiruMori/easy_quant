# 回测与实盘

实盘列表为已终止实例提供“删除实盘”。二次确认后在业务事务中删除该实例的建议、实际操作、账本、定时计划、关联后台任务和通知投递（包括盘后提醒）；不删除来源回测、策略或通知渠道，历史审计保留。运行或暂停实例不能直接删除；执行中的关联任务会阻止删除。

通知设置中，已停用渠道可在二次确认后删除，清理其投递及重试任务。被任意状态实盘使用的渠道不能删除，提示列出具体实盘名称。旧实盘未指定渠道列表时，按使用本人全部渠道处理。

## 回测

用户选择不可变策略版本、日期、初始资金、手续费、滑点、基准和随机种子。标的由策略和因子决定，表单不单独填写股票。系统在运行前检查日线及静态可识别的因子数据依赖；缺失时返回数据集、日期范围和数据管理入口，不使用 Mock 或合成行情。

提交回测后立即创建排队记录和持久 job，worker 领取后执行；详情页轮询状态并显示失败原因。引擎按每个交易日依次运行三个钩子，复用同一策略公共库。盘前按开盘价、盘后按收盘价模拟成交；盘中只用当日开收盘均值判断一次并按该均值成交，不用当日最高最低价假设盘中路径。均值含收盘信息，只代表近似模拟，假设和页面明确披露。回测禁用通知，资金、持仓、费用和指标使用 `Decimal`。结果持久保存配置、应用版本、行情快照摘要、基本面摘要、模拟报价口径、策略输出、权益和交易。

创建回测时，空快照、回测记录和 job 在同一个独立短事务中提交，入队失败全部回滚。保存结果时先写入快照主记录，再写入压缩分块；先写入回测主记录，再写入权益、交易和指标明细，最后统一提交。已存在的快照直接复用。旧版本留下的排队/运行记录若找不到关联 job，查询时展示“任务未成功入队”，不改写旧记录。

worker 在策略启动前读取覆盖摘要检查所选区间，不再执行完整策略后才报告端点缺失；上市日期限定所需起点，数据源确认或管理员标记停牌的证券不要求端点成交日线，结果假设中的 `coverage_exempt_suspended_symbols` 记录该名单。停牌前历史行情保留，停牌期间不补造 K 线。在市股票的真实覆盖缺失仍阻止运行。该检查不要求每天存在交易记录，也不能替代历史停牌事件校验。进度和失败详情使用独立短事务保存，失效行情读 Session 会先移除，保留原失败原因、缺失数据及入口。旧回测状态停留在排队/运行但关联任务已失败时，列表和详情按任务失败状态展示，不改写历史记录。阶段开始日志与节流进度展示校验、预热、读取、当前交易日/hook、快照及保存；快速测试和回测均保存阶段耗时、hook 次数/平均/最大耗时与逐日明细（含通信时间）。

每个阶段先用当前模拟组合运行策略，再模拟该阶段的成交，随后进入下一阶段。`context.position(symbol)` 返回阶段开始时的模拟持仓，`context.data["cash"]` 是现金的十进制字符串，`context.data["positions"]` 是数量字符串字典。盘中可以看到盘前已成交的买卖，次日延续上一日的组合；未触价、资金不足或持仓不足的信号不会改变组合。一个钩子内的多个信号共享阶段开始时的快照，策略修改上下文副本不影响领域引擎的组合。

回测复用受限策略子进程，源码全局变量同日保留、下一交易日重新初始化；`context.store` 在同一次回测跨日保留。读取起始日前已存储的窗口历史预热因子，并纳入快照身份。任一阶段失败时整次回测失败，不发布部分交易为成功结果。新结果保存 `strategy_context_protocol: strategy-library-v2`；既有结果保留原状。表单可传策略参数 JSON。实盘启动表单预填该参数，允许独立修改，启动不会改写来源回测。

## 实盘建议

只有成功正式回测才能启动实盘，含 Mock 结果不可启动。回测详情和实盘详情可预览所引用的不可变策略版本，显示名称、说明、代码并跳到对应版本详情；详情提供编辑入口，确认后复制新的草稿，原回测/实盘版本不变。

点击“开启实盘跟踪”先展开启动表单，要求名称、正数初始可用现金及至少一个本人启用的通知渠道；策略参数、初始持仓 JSON 和盘后核对提醒可独立设置。初始持仓作为不可变基线参加账本重建，当前不录入初始成本，成本基线为 0，不从现金扣款。实盘列表展示名称、策略和启动资金，详情展示完整启动配置、渠道及来源回测链接。旧实例不把历史动态持仓追溯当作初始持仓。

通知配置支持单独命名、改名、启停和发送连通性测试；测试会实际发送一条消息，页面返回脱敏投递状态，成功仍需在接收端确认。新实盘只通知选中且启用的渠道，旧实例保留原全渠道语义；同一事件按渠道去重。ntfy 支持主题名或完整 HTTP(S) 地址，中文标题按 [ntfy 官方说明](https://github.com/binwiederhier/ntfy/blob/main/docs/publish.md)使用 RFC 2047 编码。投递失败不暴露通知地址或原始异常。

启动时建立盘前与盘中单次计划：盘前 09:00 只读已同步数据；盘中时间由系统 `EASY_QUANT_INTRADAY_RUN_TIME` 统一设置，默认 14:50，每个交易日仅成功执行一次。策略按需请求真实临时报价；重试不重复执行已完成阶段或改写 KV。买卖建议可按比例加减仓，附带原因、比例、基数和换算数量；实盘不自动下单。盘后默认关闭；启动表单可勾选盘后核对提醒（API 字段 `after_market_enabled`），开启后创建盘后计划及核对提醒。

阶段 KV、建议、完成标记和通知 outbox 在同一短事务提交；外部通知在事务外投递。提交后中断或投递入队失败时，下一次分析先恢复 outbox，再检查完成标记，避免因阶段去重漏掉已提交建议的通知。

用户可快速确认、拒绝或录入不同的实际成交。每次处理带幂等键和建议版本；实际操作生成账本，后续策略上下文使用账本重建出的现金、持仓和成本。确认和修正先验证成交数量、价格、费用及完整候选账本，再在一个事务中写入实际操作、账本、建议版本、组合缓存和审计。资金不足、持仓不足或任一存储步骤失败时全部回滚，不占用幂等键；拒绝只记录操作和状态，不产生现金或持仓账本。

幂等键按用户隔离，相同请求重复提交返回完全相同的结果；换建议、动作或成交字段复用键会返回冲突。页面显示处理中和失败原因，成功后立即更新建议状态并禁用处理按钮。网络失败后的相同请求重试保留原键。旧操作记录未保存完整请求身份，因此旧键重放会提示查看已保存的建议及账本，不猜测成交。

人工反馈使用独立 SQLAlchemy Session 和 MariaDB 短事务，通过事务内互斥行串行校验组合。每笔新账本记录保存入账序号，同一时间或时钟回退时也按提交顺序重建；旧记录保留原有时间与 ID 排序。实盘分析从账本恢复组合，保存新建议前再次读取最新状态，保留已处理建议，并拒绝向已暂停或终止的实例追加建议。策略执行和外部通知位于短事务之外。

当前账本从初始现金重建，不支持把非零初始持仓作为不可变基线；不要依赖启动参数中的持仓缓存作为实际账本。此次修复不自动改写历史坏账，已有无效账本仍会阻断后续操作，需先人工核验。

通知支持 ntfy 和邮件。通知目标加密保存，API 只返回掩码。临时投递错误进入持久重试任务，永久配置错误标记失败；业务事件与订阅共同形成幂等键，重复分析不会重复发送。

Worker 在调度与任务执行之间释放共享读会话，防止调度快照早于回测提交、导致已入队任务误报记录不存在；任务完成和异常退出时均清理会话。修复部署后需重启 worker，已失败回测从页面重新创建。

## 指数与基准

指数使用独立代码空间：`sh000001` 上证指数、`sh000016` 上证50、`sh000300` 沪深300、`sh000905` 中证500、`sh000852` 中证1000、`sz399001` 深证成指、`sz399006` 创业板指。股票仍用六位代码。刷新证券清单会加入这些主要指数；在“数据管理 → 指数”Tab 可直接选择指数并同步区间日线，不必先刷新股票清单；通用数据采集仍支持带前缀代码，沿用来源开关、重试与审计。指数采用不复权日线，盘后日线任务纳入指数，股票基本面任务排除指数。

回测基准 `000300` 自动识别为 `sh000300`；上证指数须显式填 `sh000001`，避免与平安银行 `000001` 混淆。所选基准要求每个交易日有决策时点可见的真实收盘价，缺失时回测失败并直接显示指数同步入口。收益为区间最后收盘/首个收盘−1，曲线以初始现金归一化，与组合权益对照。旧回测不补算或改写历史结果，需重新回测。

指数保留在行情和因子查询中，例如 `context.factor("technical.ma", symbol="sh000300", window=5)`；`universe()` 和 `securities()` 不将指数列为可交易股票。回测执行、实盘建议、初始持仓和人工成交均阻止指数交易。
