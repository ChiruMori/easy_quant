# 回测与实盘

实盘列表为已终止实例提供“删除实盘”。二次确认后在业务事务中删除该实例的建议、实际操作、账本、定时计划、关联后台任务和通知投递（包括盘后提醒）；不删除来源回测、策略或通知渠道，历史审计保留。运行或暂停实例不能直接删除；执行中的关联任务会阻止删除。

通知设置中，已停用渠道可在二次确认后删除，清理其投递及重试任务。被任意状态实盘使用的渠道不能删除，提示列出具体实盘名称。旧实盘未指定渠道列表时，按使用本人全部渠道处理。

## 回测

用户可填写回测名称（最多 160 字），留空按策略名称、版本和日期区间生成；列表、详情和比较选择器优先展示名称，旧记录没有名称时仍用编号。用户选择不可变策略版本、日期、初始资金、手续费、滑点、基准和随机种子。标的由策略和因子决定，表单不单独填写股票。系统在运行前检查日线及静态可识别的因子数据依赖；缺失时返回数据集、日期范围和数据管理入口，不使用 Mock 或合成行情。

提交回测后立即创建排队记录和持久 job，worker 领取后执行；详情页轮询状态并显示失败原因。引擎按每个交易日依次运行三个钩子，复用同一策略公共库。盘前按开盘价、盘后按收盘价模拟成交；盘中只用当日开收盘均值判断一次并按该均值成交，不用当日最高最低价假设盘中路径。均值含收盘信息，只代表近似模拟，假设和页面明确披露。回测禁用通知，资金、持仓、费用和指标使用 `Decimal`。结果持久保存配置、应用版本、行情快照摘要、基本面摘要、模拟报价口径、策略输出、权益和交易。

创建回测时，空快照、回测记录和 job 在同一个独立短事务中提交，入队失败全部回滚。保存结果时先写入快照主记录，再写入压缩分块；先写入回测主记录，再写入权益、交易和指标明细，最后统一提交。已存在的快照直接复用。旧版本留下的排队/运行记录若找不到关联 job，查询时展示“任务未成功入队”，不改写旧记录。

worker 在策略启动前读取覆盖摘要检查所选区间，不再执行完整策略后才报告端点缺失；上市日期限定所需起点，数据源确认或管理员标记停牌的证券不要求端点成交日线，结果假设中的 `coverage_exempt_suspended_symbols` 记录该名单。停牌前历史行情保留，停牌期间不补造 K 线。在市股票的真实覆盖缺失仍阻止运行。该检查不要求每天存在交易记录，也不能替代历史停牌事件校验。进度和失败详情使用独立短事务保存，失效行情读 Session 会先移除，保留原失败原因、缺失数据及入口。旧回测状态停留在排队/运行但关联任务已失败时，列表和详情按任务失败状态展示，不改写历史记录。阶段开始日志与节流进度展示校验、预热、读取、当前交易日/hook、快照及保存；快速测试和回测均保存阶段耗时、hook 次数/平均/最大耗时与逐日明细（含通信时间）。

每个阶段先用当前模拟组合运行策略，再模拟该阶段的成交，随后进入下一阶段。`context.position(symbol)` 返回阶段开始时的模拟持仓，`context.data["cash"]` 是现金的十进制字符串，`context.data["positions"]` 是数量字符串字典。盘中可以看到盘前已成交的买卖，次日延续上一日的组合；未触价、资金不足或持仓不足的信号不会改变组合。一个钩子内的多个信号共享阶段开始时的快照，策略修改上下文副本不影响领域引擎的组合。

回测复用受限策略子进程，源码全局变量同日保留、下一交易日重新初始化；`context.store` 在同一次回测跨日保留。读取起始日前已存储的窗口历史预热因子，并纳入快照身份。任一阶段失败时整次回测失败，不发布部分交易为成功结果。新结果保存 `strategy_context_protocol: strategy-library-v2`；既有结果保留原状。表单可传策略参数 JSON。实盘启动表单预填该参数，允许独立修改，启动不会改写来源回测。

回测列表显示北京时间创建时间，旧记录缺失时标为“未记录”。回测与实盘共用组合图表和临时比较选择器，可在金额（元）/收益率（%）间切换，最多临时添加 8 条比较，移除或离开页面后不保存。回测金额为组合权益，实盘金额为累计收益；默认回测基准保留。市场比较搜索已有指数或股票，回测金额按初始现金归一，实盘按启动权益计算比较收益，收益率均按各自起点归一。比较使用当前已同步且在对应时点可获知的收盘价，不改写原回测快照；起点缺行情时拒绝添加，之后无新报价时延用最近已发布价格。回测还可添加本人相同起止日期、初始资金和初始持仓的已完成回测，服务端复核条件；实盘不比较回测。

## 实盘建议

只有成功正式回测才能启动实盘，含 Mock 结果不可启动。回测详情和实盘详情可预览所引用的不可变策略版本，显示名称、说明、代码并跳到对应版本详情；详情提供编辑入口，确认后复制新的草稿，原回测/实盘版本不变。

点击“开启实盘跟踪”先展开启动表单，要求名称、正数初始可用现金及至少一个本人启用的通知渠道；策略参数、初始持仓 JSON 和盘后核对提醒可独立设置。初始持仓作为不可变基线参加账本重建，当前不录入初始成本，成本基线为 0，不从现金扣款。实盘列表展示名称、策略和启动资金，详情展示完整启动配置、渠道及来源回测链接。旧实例不把历史动态持仓追溯当作初始持仓。

通知配置支持单独命名、改名、启停和发送连通性测试；测试会实际发送一条消息，页面返回脱敏投递状态，成功仍需在接收端确认。新实盘只通知选中且启用的渠道，旧实例保留原全渠道语义；同一事件按渠道去重。ntfy 支持主题名或完整 HTTP(S) 地址，中文标题按 [ntfy 官方说明](https://github.com/binwiederhier/ntfy/blob/main/docs/publish.md)使用 RFC 2047 编码。投递失败不暴露通知地址或原始异常。

启动时建立盘前与盘中单次计划：盘前 09:00 只读已同步数据；盘中时间由系统 `EASY_QUANT_INTRADAY_RUN_TIME` 统一设置，默认 14:50，每个交易日仅成功执行一次。策略按需请求真实临时报价；重试不重复执行已完成阶段或改写 KV。买卖建议可按比例加减仓，附带原因、比例、基数和换算数量；实盘不自动下单。盘后默认关闭；启动表单可勾选盘后核对提醒（API 字段 `after_market_enabled`），开启后创建盘后计划及核对提醒。

同一实例、交易日、阶段的新建议聚合成每渠道一条汇总通知，包含总数和前 20 条标的/方向/数量/参考价，更多内容提示登录查看。阶段 KV、建议、完成标记和通知 outbox 在同一短事务提交；外部通知在事务外投递。提交后中断或投递入队失败时，下一次分析先恢复 outbox，再检查完成标记，避免因阶段去重漏掉已提交建议的通知。

用户通过接受、拒绝、修改图标操作建议，接受和拒绝先二次确认，取消不发送请求；修改实际成交仍使用弹窗。修正使用弹窗，标的和方向固定，数量、价格与预计手续费预填，数量必须为正整百。操作列表按日期及 ID 倒序分页（默认 20 条，最多 100 条），标的、日期和说明使用搜索框，状态与操作类型通过独立筛选组合查询，并重置页码；显示建议日期、推荐价、股数、状态及实际成交，区分买卖信号与手动买卖。说明独立成列，超过 15 字省略，悬停、焦点和点击可展开全文；状态只在状态列展示。实盘资金、现金、收益及追加资金提示统一显示两位小数，内部 Decimal 精度保持不变。每次处理带幂等键和建议版本；实际操作生成账本，后续策略上下文使用账本重建出的现金、持仓和成本。确认和修正先验证成交数量、价格、费用及完整候选账本，再在一个事务中写入实际操作、账本、建议版本、组合缓存和审计。资金不足、持仓不足或任一存储步骤失败时全部回滚，不占用幂等键；拒绝只记录操作和状态，不产生现金或持仓账本。

幂等键按用户隔离，相同请求重复提交返回完全相同的结果；换建议、动作或成交字段复用键会返回冲突。页面显示处理中和失败原因，成功后立即更新建议状态并禁用处理按钮。网络失败后的相同请求重试保留原键。旧操作记录未保存完整请求身份，因此旧键重放会提示查看已保存的建议及账本，不猜测成交。

人工反馈使用独立 SQLAlchemy Session 和 MariaDB 短事务，通过事务内互斥行串行校验组合。每笔新账本记录保存入账序号，同一时间或时钟回退时也按提交顺序重建；旧记录保留原有时间与 ID 排序。实盘分析从账本恢复组合，保存新建议前再次读取最新状态，保留已处理建议，并拒绝向已暂停或终止的实例追加建议。策略执行和外部通知位于短事务之外。

账本以初始现金和不可变初始持仓为基线重建，不依赖动态持仓缓存。已有无效账本仍会阻断后续操作，需先人工核验。

待操作买入建议在生成事务内锁定成交额和预计费用（当前默认万分之三），卖出建议锁定股数，跨轮分析仍扣除这些预留。同次分析顺序校验最新可用余额，资金或持仓不足的建议不保存。确认/修正后以实际成交记账并释放本条预留，拒绝只释放预留；其他建议锁定额始终受保护。暂停和终止均需二次确认，停止分析但保留未处理建议，用户仍可核对这些实际成交；不静默取消锁定。

未终止实例可手动添加已经发生的买卖。先预检，再强提醒可能偏离策略、影响收益与重复记账；现金不足时列明需要追加的金额和调整后资金池，用户确认后才原子写入注资、成交和审计。追加金额必须与提交时最新所需额一致，变化后重新预检；卖出不能超过未锁定持仓。手动操作与建议处理共用用户隔离幂等键规则。

实盘详情使用与回测一致的红涨绿跌文字显示收益、收益率、资金池、可用/锁定资金和持仓、启动以来累计收益曲线。估值只读取已发布日线收盘价，收盘之间延用最近已发布价格；收益扣除注资，收益率采用累计收益/累计投入资金（包含启动持仓估值），不是年化或时间加权收益；资金池大小按初始现金加累计追加现金显示，与手动操作预检口径一致。初始持仓按启动时已可知行情估值，45 天窗口无基准价或当前持仓缺行情时显示缺失标的，不伪造收益。历史曲线按日线发布日和当前时点重建；旧实例缺启动时间时从最早账本时间展示，不能补造更早收益。估值在复制账本快照后读取行情，不占用人工记账短事务。

通知支持 ntfy 和邮件。发送前持久保存待投递记录并安排 5 分钟后的恢复任务，随后在短事务中领取发送；外部请求不占用记账锁。记录保存创建、最近尝试、完成时间、次数、状态和安全错误码，日志只记录投递 ID、事件 ID、状态和错误码。临时错误自动重试，最多尝试 3 次；永久错误、凭据无法解密、渠道未配置或停用均持久记录原因，没有有效选中渠道也记录“未发送”。已成功事件重放不再次发送；中断后恢复沿用相同业务幂等键，外部服务是否去重取决于渠道支持，不能保证终端恰好收到一次。

实盘详情以每页 20 条分页展示本实例投递诊断，记录持久保存，不依赖临时日志；可跳到通知设置测试连通性。状态“渠道已接收”只表示服务接受请求，不等于用户终端已收到；旧日志丢失时无法推定历史实际接收结果。通知目标仍加密保存，列表只返回掩码；本人显式显示或编辑时通过独立详情接口读取，响应禁止缓存，关闭编辑窗口清除目标。错误响应、审计与日志不包含目标及异常原文。通知管理使用已配置渠道和最近投递两张独立分页表格（每页 10 条），新增、编辑均在弹窗中进行；停用渠道仍可编辑名称和目标，支持显隐，保存不改变其启用状态。投递按创建时间降序，失败可重试读取。

Worker 在调度与任务执行之间释放共享读会话，防止调度快照早于回测提交、导致已入队任务误报记录不存在；任务完成和异常退出时均清理会话。修复部署后需重启 worker，已失败回测从页面重新创建。

## 指数与基准

指数使用独立代码空间：`sh000001` 上证指数、`sh000016` 上证50、`sh000300` 沪深300、`sh000905` 中证500、`sh000852` 中证1000、`sz399001` 深证成指、`sz399006` 创业板指。股票仍用六位代码。刷新证券清单会加入这些主要指数；在“数据管理 → 指数”Tab 可直接选择指数并同步区间日线，不必先刷新股票清单；通用数据采集仍支持带前缀代码，沿用来源开关、重试与审计。指数采用不复权日线，盘后日线任务纳入指数，股票基本面任务排除指数。

回测基准 `000300` 自动识别为 `sh000300`；上证指数须显式填 `sh000001`，避免与平安银行 `000001` 混淆。所选基准要求每个交易日有决策时点可见的真实收盘价，缺失时回测失败并直接显示指数同步入口。收益为区间最后收盘/首个收盘−1，曲线以初始现金归一化，与组合权益对照。旧回测不补算或改写历史结果，需重新回测。

指数保留在行情和因子查询中，例如 `context.factor("technical.ma", symbol="sh000300", window=5)`；`universe()` 和 `securities()` 不将指数列为可交易股票。回测执行、实盘建议、初始持仓和人工成交均阻止指数交易。

已完成回测提供“股票收益明细”，包含所有期末持仓及已清仓股票，按总收益降序分页（每页 20 条）。采用移动平均成本，买入费用计入成本，卖出费用扣除已实现收益，滑点已反映在成交价中，不重复扣减；总收益为已实现与期末浮动收益之和。新回测保存运行时的冻结明细；旧回测从原成交和原行情快照重建，流式核验快照摘要，不读取最新行情或改写原结果。缺少期末价格时明确显示缺少估值，并排在末尾；快照损坏时报告错误。

共享组合图表以 ￥ / % 切换金额和收益率（保留完整可访问名称），临时比较显示为内含关闭控件的标签。实盘已处理建议隐藏操作按钮，待操作建议提交时继续防止重复请求。

指数自动同步以北京时间 15:00 收盘为日期边界，盘后请求包含当天交易日，不再沿用股票数据默认 22:00 发布边界。各来源必须覆盖请求的最后交易日，否则切换来源并报告失败，不能将缺少当天的数据视为成功。来源尚未发布时可稍后重试或将任务改到下一交易日盘前；不会补造当天行情。


## 页面加载与回测维护

实盘详情先读取轻量摘要（配置、第一页操作和资金锁定信息），收益估值和投递分页独立请求。历史估值显示骨架占位，失败可局部重试，不阻止查看和处理操作；投递读取失败也不阻塞收益曲线。JSON 持久列表采用批量遍历，投递分页在数据库中过滤、计数和限量读取。

回测详情的“修改回测名称”可修改历史或运行中的回测，名称去除首尾空白，长度 1–160 字。名称独立于结果 JSON 保存，worker 完成回测不会覆盖用户修改；旧记录继续读取原 payload 名称，缺失时界面显示编号。比较搜索包含名称、编号、版本及创建日期，选项优先显示名称。

## 回测耗时与输入规模

单月区间不代表只读取一个月行情。预热窗口由策略 HISTORY_TRADING_DAYS 及静态因子依赖确定，无法推断时为 250 个交易日。股票池是区间行情中的全部非排除证券，快照包含从预热起点至回测结束的完整行情与血缘，不能只保存成交股票，否则无法追溯选股输入。快照阶段还会重新读取完整输入，执行规范 JSON 编码、摘要计算和临时文件写入；保存结果阶段另含压缩与持久化。

快照 SQL 投影只读取必需列，使用流式标量行代替 ORM 实例；行情代码批次限制为 100，减少大 IN 列表的范围估算风险；编码器复用且保持旧 JSON 字节和哈希协议。运行耗时面板与日志额外记录预热起点、预热窗口、预热行数、运行行数、快照行数和原始字节数，同时分开观测快照读取与行转换、编码/摘要/临时写入耗时。新统计只适用于新执行的任务，不能从旧耗时反推出数据库与编码各自占比。需用相同策略、区间和行情复测；不承诺固定加速比例，也不通过缩短必需预热历史改善表面耗时。


## 实盘终止与列表

实盘列表在数据库中按本人、名称关键词与状态筛选，按启动时间倒序，每页 20 条，详情和删除操作位于表格行内。无分页参数的旧列表接口继续返回数组，供概览兼容使用。

终止前必须核对实际成交和待处理建议。确认终止时先复制组合输入，在记账事务外按当前已发布行情计算收益指标与曲线，再在短事务内校验输入未变，原子保存终止时间、资金持仓及收益快照；若期间有记账变化则提示重新确认。终止后停止每日运行和后续估值，详情仍展示冻结的收益指标与曲线，支持金额/收益率切换，保留历史操作和通知诊断，隐藏行情比较、刷新及写入入口。终止不可恢复，新的建议处理与手动录入均被拒绝；已完成操作的同请求重放不修改账本。旧已终止实例缺少收益快照时，按实例或审计记录中的终止时间重建一次并持久化，不使用终止之后的行情；若终止时间也缺失，则明确提示无法恢复收益，不伪造指标。

实盘详情顶部只保留暂停、终止、刷新图标；暂停和终止均二次确认，终止明确告知不可恢复和冻结范围。手动录入图标位于操作列表工具栏，继续保留风险及追加资金确认。

共享图表的金额/收益率、添加对比图标、比较标签统一为 32px 高。回测候选最多 20 条，只显示名称或缺失时的编号，超过 20 个字符省略并可通过提示查看完整名称，不附带创建时间。

快测没有回测输入规模统计时，耗时面板仅展示已有耗时，不把空统计对象作为完整回测规模读取。

实盘分页列表逐行显示当前收益率，使用与收益卡一致的红涨绿跌颜色和两位小数。终止实例直接显示冻结收益率；运行或暂停实例按行独立加载指标，加载失败可单独重试，不阻塞搜索、筛选及分页，也不为列表计算历史曲线。
