# 日线存储

## 当前结构

`daily_bars` 是唯一的业务日线表，主键为 `(symbol, trading_day)`。保留 OHLC `DECIMAL(20,6)`、volume/amount `DECIMAL(28,4)`、UTC `available_at`，使用 `INT UNSIGNED NOT NULL provenance_id` 关联共享来源。日线物理表没有 source、adjustment 或 archive_sha256 列。

`bar_provenance` 保存不可变的 `(source, adjustment, archive_sha256)`。二进制生成键 source_key、adjustment_key、archive_key 和独立 NULL 标记构成唯一键，保留大小写、尾部空格、NULL 与空字符串的差别。元数据编号不进入业务快照；逻辑读接口仍返回三个来源原值。没有外键，也不在大日线表上增加 provenance_id 索引。

新增引用由写入代码在同一事务内批量解析并核对存在性，元数据不原地修改、不提供删除入口；读完整行情或快照发现悬空引用即报错。已有其他业务表外键不在此次清理范围内，后续按专项补齐业务语义后逐步淘汰。

## 读写入口

- 普通上传/同步、通达信全量及增量、原生 LOAD DATA 全部只写当前结构；原生加载先解析来源编号，不存在旧列 SET 分支。
- 运行价格投影及覆盖端点直接读日线。月区段缓存优先命中、缺页批量取数据并按 LRU 淘汰。快照按股票主键范围分批读取，显式 LEFT JOIN 一次还原来源，不逐行往返查询。
- `ix_daily_bars_coverage(symbol,trading_day)` 用于覆盖与 MIN/MAX 端点；`ix_daily_bars_day_symbol(trading_day,symbol)` 用于日期范围定位股票。价格读取使用主键范围；不要增加包含价格/来源的大宽索引。
- 回测、快测与实盘共享当前逻辑行情契约；来源 ID 与数据库布局不得改变 Decimal、可获知时点或快照身份。

## 初始化和版本

当前 schema 为 `0011_compact_daily_bars`。新空库运行 `pnpm migrate`。历史 Alembic revisions 是空库重建所需的版本链，保留其固定 DDL；其中出现旧字段只描述历史结构，不是应用的旧格式兼容路径。0011 只允许空的旧日线表转换或当前结构推进版本，不再提供有数据旧库的转换入口。

一次性搬运、校验、切表、回滚工具、临时 SQL 及根命令已退役。当前业务代码不读取旧表，不恢复旧格式；数据恢复使用当前结构的数据库备份。

## 旧表是否可删除

本项目代码不依赖旧表；当前账号可见的外键、视图、触发器、事件和存储过程未发现其引用。`daily_bars_legacy` 仅剩旧格式备份用途，`bar_migration_progress` 仅剩搬运检查点用途，均不被业务使用。依据用户已通过的完整 verify、版本/结构核对及本次抽样，技术上可以删除这两张表。

本轮没有执行删除。下列语句仅供明确执行清理时使用，删除旧表也会放弃这份本地旧格式备份；需保留的数据恢复能力应由当前结构备份承担：

```sql
SET SESSION lock_wait_timeout = 5;
DROP TABLE IF EXISTS daily_bars_legacy;
DROP TABLE IF EXISTS bar_migration_progress;
```

必须保留 `daily_bars` 和 `bar_provenance`。`history_import_stocks` 与 `tdx_daily_checkpoints` 仍用于全量导入幂等、每日增量基线和失败恢复，也必须保留，它们不是本次迁移临时表。现场未发现其他影子/回滚日线表，不使用通配符 DROP。日常持久诊断可用 `pnpm diagnose:db`，只读元数据和有界样本，不修改数据。
