# 通达信历史数据

管理员 CLI 使用[通达信官方个人版完整日线归档](https://www.tdx.com.cn/article/vipdata.html)，参考 [tdx2db](https://github.com/jing2uo/tdx2db) 的 `.day` 格式自行实现解析。完整包包含指数等其他证券，导入器只选择沪深京 A 股代码，排除指数、基金、B 股、债券及分钟数据。覆盖范围以官方包实际文件为准，不保证包含所有退市或更名证券。

## 操作

先配置被 Git 忽略的 `backend/.env` 并升级数据库，然后在仓库根目录执行：

```sh
pnpm migrate
pnpm data:tdx download
pnpm data:tdx inspect
pnpm data:tdx import
```

默认归档位于 `backend/.local-data/tdx/hsjday.zip`。下载流式写入 `.zip.part`，验证长度及 ZIP 目录后替换目标；`inspect` 逐文件校验 CRC、记录长度、日期顺序与行情值，输出 SHA256、股票数、总记录数及首末日期。可通过 `--archive <path>` 指定已有官方 ZIP，无需解压。

默认导入通过 SQLAlchemy/PyMySQL 分批 upsert，`--batch-size` 范围为 1–10000，默认 2000。服务器已启用 `LOCAL INFILE` 时可显式使用原生导入以减少网络往返：

```sh
pnpm data:tdx import --local-infile
```

该参数只开启本次 CLI 连接的本地文件能力，不修改服务器设置，API 默认不开启。原生导入仅生成固定字段的内部 TSV，使用结束后删除；任何数据库警告都会使事务回滚。

## 数据口径与恢复

价格为元，成交量为股，成交额为元，成交额使用 Decimal 按四位小数四舍五入。日线为不复权（`adjustment=none`），来源为 `tdx-official`；可获知时间为交易日 15:00 Asia/Shanghai，数据库存储 UTC。每行关联归档 SHA256，保留现有证券名称；新增代码名称为空、状态为 `unknown`。

一只股票预检完成后加入有界事务组，组内行情、交易日历、证券及完成检查点一同提交。每组最多约十万行或五十只股票（末只股票可能使行数略超阈值）；默认 SQL 每次执行仍按 `--batch-size` 分块。失败组不会写入完成检查点。中断后运行相同命令，同包已完成股票会跳过，未完成股票从头重放并按股票/日期主键保持幂等。完成后的 JSON 报告保存在归档旁，失败股票及原因会列入报告，存在失败时命令返回非零。

Ctrl+C 请求会在当前事务处理结束后的进度边界退出，避免驱动将中断误包装成连接错误。连接异常或被终止时，未提交事务由数据库回滚；确认连接恢复后直接重跑即可。报告中的数据库异常只保留类型和数字代码。

更新历史使用 `download` 获取新包，再 `inspect`、`import`；新包 SHA256 会触发重新导入。原始归档、临时 TSV、报告都被 Git 忽略，代码、版本化样本和测试进入 Git，行情进入配置的 MariaDB。

当前日线表同一股票只支持一种复权口径。CLI 拒绝覆盖前复权或未知口径的已有股票；页面公开接口标记为前复权，CSV 未声明口径标记为未知，二者也会拒绝混入已有不复权历史。导入不提供复权因子、证券名称补全、页面上传或大文件进度 UI。原始不复权价格可能在分红送转时跳变，回测需结合该口径理解结果。

本地 API 启动时会更新旧版默认日线描述，说明公开接口和通达信的口径；自定义说明和来源启停配置保留。全市场覆盖统计使用股票/日期二级索引，升级已有数据库后应重新启动 API 和 worker。

## 每日增量

完成全量导入且报告无失败后，升级到 `0004_tdx_daily_checkpoints`，运行：

```sh
pnpm migrate
pnpm data:tdx:update
pnpm data:tdx:update --start-day 2026-09-30 --end-day 2026-09-30
```

默认从全量股票检查点的最新日期后开始，后续重查最近七个自然日；较早的 failed/pending 日期和检查点中间的空缺也会补齐。明确起止日期可用于重放旧日期或分段补数；每次最多 90 个自然日。仅凭全量检查点存在不能证明全量导入完成，启动增量前必须核验全量报告无失败。

每日包来源为 `https://www.tdx.com.cn/products/data/data/g4day/YYYYMMDD.zip`。解析 ZIP 内沪深京 `.cod`/`.md1`，不解压到任意路径、不执行外部 datatool；格式版本为 `tdx-md1-v1`。价格规范为分后转换元，成交额按 DAY 格式转为 float32，再规范为四位小数，以保持全量与增量一致；MD1 成交量按 uint64 股读取，超出 DAY 兼容范围拒绝。零成交量且零成交额的未成交证券跳过，记录数量；有成交却价格无效时整个日期拒绝。

任务使用 Asia/Shanghai 18:00 作为当天更新准入时点，早于此时默认只检查前一天，显式未来或未到盘后时点的结束日期拒绝。该时点不保证官方已发布；404 保留 pending，下次重试。周末及官方 `gbbq.zip` 内 `zhb.zip/needini.dat` 声明的休市日期跳过；未知年度不猜测休市。日历下载/解析失败使任务失败，不使用过期日历静默前进。日历只供本增量流程使用，不修改平台其他交易日历来源。

一天全部 A 股行情、证券、交易日和 succeeded 检查点同事务提交。先完整校验配对、日期、CRC、长度、引用位置、代码重复和数值；损坏包不产生部分行情。相同日期/摘要已成功则不写库，摘要变化会按股票/日期主键纠正；`imported_rows` 是本次提交行数，包含覆盖，不等于新增行数。修订失败会保留既有行情并标记 failed，继续优先恢复。CLI 与定时增量任务使用 MariaDB 命名锁互斥；全量重新导入应安排在增量任务停用期间。

原始增量与日历 ZIP 保存于 `backend/.local-data/tdx/daily/`，完成报告为 `latest-update.json`。失败日期列在 `unresolved`，命令返回非零；Ctrl+C 在事务后的进度边界退出，未提交事务回滚。全部本地原始文件均不提交 Git。

管理员在“定时任务”选择“通达信 A 股盘后增量”，例如 Cron `0 18 * * 1-5`、时区 `Asia/Shanghai`，再保持 `pnpm dev:worker` 或部署 worker 运行。任务类型为 `tdx-daily-update`，默认无配置，由服务计算补数范围。任务管理显示成功计数或失败日期；任务失败后，下次计划运行会恢复。可通过管理员调度 API 的 configuration 指定 `start_day`/`end_day` 做定向重放。创建任务才启用定时更新；迁移不会自动创建计划。若 18 点官方尚未发布，重试计划可使用 `0 18,20 * * 1-5`。

格式布局及休市解析改编自 tdx2db，许可和固定参考提交见 [第三方声明](../THIRD_PARTY_NOTICES.md)。股本变动、复权因子和代码更名迁移没有接入。
