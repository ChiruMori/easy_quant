# 回测输入与实盘运行计划

回测以日期、代码确定的顺序分月批量读取实际输入，同时编码到有界临时快照。结束后直接完成摘要及压缩保存，不再重新扫描行情表。快照包含本次实际消费的行情及来源身份；应用发布之间的行排序变化可能改变快照摘要，但解压格式及摘要校验不变。此前已保存的快照继续可读，不需删除或重建K线。

SQL读取先用日期覆盖索引定位代码，再分批沿主键范围读取物理列；来源元数据独立读取一次，在内存按provenance_id关联，避免大结果集逐行做元数据join。不调用逐行get或单标的单日查询。内存最多保留当月读取批次、当前滚动历史及临时文件缓冲；不跨任务缓存行情。原始因子输入缓存最多保留20000行（单个标的输入不拆分），淘汰后从运行快照重新归一化，不查数据库；因子结果仍即时计算，不缓存结果。返回记录副本保留嵌套数据隔离，日期与Decimal等不可变值直接复用。

snapshot_read_seconds与snapshot_encode_seconds现在记录输入加载期间的读取/转换与编码耗时，已包含在预热、读取阶段中，不应与阶段总耗时相加。末尾snapshot阶段主要完成摘要，saving阶段包含快速gzip压缩及持久化。输入范围依策略推导窗口或HISTORY_TRADING_DAYS而定，不能把一个月回测误当作只需读取一个月行情。

子进程单阶段仍执行30秒上限；序列化、管道写入与读取均计入deadline。失败任务详情保存日期、阶段、状态与错误；worker日志记录定位信息、异常类型及退出码，不输出策略异常中的任意用户数据。超时不自动增大限制，也不静默重试阶段。生产环境超时与OOM等具体原因仍应结合任务详情及容器退出/资源记录确认。

新实盘、默认运行计划及策略已实盘状态在同一短事务中提交，避免请求事务仍处于旧读取快照时误以为实例不存在。worker每轮调度补齐运行中和暂停实例的缺失计划，稳定ID避免重复；暂停实例的计划禁用，已终止实例不重建，已删除实例的遗留计划清理。

默认Asia/Shanghai工作日09:00执行盘前分析，统一盘中时间默认14:50执行盘中分析；盘后阶段默认关闭，开启后默认15:30。任务会再次检查交易日和阶段幂等性，只生成建议，不自动下单。API与worker均需更新到同一版本；worker运行后即可修复旧实例缺计划，无需删除重建实盘。补齐后按下一个到期时间执行，不补跑此前已错过的阶段。
