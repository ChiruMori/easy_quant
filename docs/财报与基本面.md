# 财报与基本面

## 已接入数据

| 数据集 / 平台库后缀 | 内容 | 直接来源 |
| --- | --- | --- |
| balance-sheets | 合并资产负债表，年报、中报、一季报、三季报 | 东方财富、新浪 |
| income-statements | 合并利润表，年初至报告期累计 | 东方财富、新浪 |
| cash-flow-statements | 合并现金流量表，年初至报告期累计 | 东方财富、新浪 |
| financial-indicators | EPS、每股净资产、ROE、增长率、利润率、偿债指标等来源可用指标 | 东方财富、新浪 |
| company-profiles | 公司名称、成立/上市日期、注册资本、员工人数、简介、主营及经营范围 | 东方财富 |
| dividend-plans | 分红送配方案、进度、每10股派息/送转、登记与除权日 | 东方财富 |
| shareholder-counts | 股东户数、户均持股及来源可用股本 | 东方财富 |
| business-compositions | 按业务项目、分类保存的主营收入、成本、利润及占比 | 东方财富 |

这是来源能力目录，不保证每只股票每个报告期均有全部科目；银行等行业的特有字段保存在 `raw_fields`。公司概况在来源响应进入缓存前只保留上述经营字段，排除电话、邮箱、地址及人员字段。当前财务接口均为原始直连，无需 AKShare 转发；既有行业、日线等数据源不受影响。

日常由默认启用的“盘后综合数据同步”计划自动采集，不需要管理员每日逐股票维护。应用启动时补齐缺失计划，首次交给worker执行最近已发布交易日，再按系统数据发布时间（默认工作日22:00、上海时区）运行。已有自定义计划及明确停用选择保留；如已有计划停用，只需在定时任务中启用一次。计划启停与手动执行统一在“系统管理—定时任务”，实际进展在“后台任务”查看；数据管理不再重复添加自动采集卡片。

“范围拉取”位于数据管理右上“数据维护”菜单，用于异常补采或更早报告；管理员选择数据集、股票与日期。财报日期区间筛选**报告期**，不是公告日；公司概况是当前快照。来源优先东方财富，支持新浪的数据集失败时按轮切换，首个完整有效响应即停止，不拼接两个来源的科目。来源开关继续在数据管理中配置；旧财务指标目录升级为两个直连来源，保留已有直连来源设置，全停用配置不会自动开启。盘后综合计划生成 `market-data-collection` 聚合任务，保留旧 `market-data-nightly` 处理兼容。一个运行只有一条后台任务；每页/每股完成后保存游标并让出 worker，重启后继续。已有排队或运行中的聚合任务会被复用，旧 `nightly:` 分散子任务直接跳过。

三表使用东方财富 `RPT_DMSK_FN_BALANCE/INCOME/CASHFLOW`，主要指标使用 `RPT_F10_FINANCE_MAINFINADATA`，公司概况、分红、股东使用对应全市场报表接口，每页500条、按报告期覆盖已知股票。自动三表提供关键科目（`source_format=bulk-v1`），不等同于逐股 F10 完整明细；既有明细不删除，可由范围拉取补采。分红、股东自动按季度末报告期收集，其他日期的户数可通过范围拉取获取。先采最近结束季度，再按季度倒序补近五年，之后处理停复牌、已有日线补齐、估值、质押、行业与主营。

逐页总量、页大小及重复行会校验。无匹配股票或来源异常不能视为覆盖成功；后台展示范围进度、当前数据集/报告期/页码、累计保存与未变化数量及失败范围。完成全部范围前保持排队/运行，部分失败最终标为失败并保留成功数据。返回空数据不代表所有股票已披露。

每个采集 HTTP 请求（含分页、重试）至少间隔5秒，没有并发突发；失败按5/10分钟退避，单页/标的最多尝试3次，其他范围继续处理。逐股日线及主营串行复用同一任务，不创建股票子任务。自动日线限定已启用且受预算控制的东方财富直连；不自动切换到内部请求不可控的 SDK。质押已改为直连全市场分页；行业 SDK 在目录及每个行业成分调用前限频。删除/取消任务或失去租约后，在下一次请求前停止。单个已发出的请求等待其超时/返回。

刷新检查点保存在现有 `runtime_documents` 的 `collection_checkpoints` 命名空间；最新约两个季度每天复查、历史30天、公司概况7天、主营逐股30天。相同内容不重复产生版本。首次全量补采包括日线和主营逐股范围，可能跨日，后续触发继续复用该运行；不承诺执行一次立即全市场填满。更早财报通过范围拉取补齐。

股票详情保留 K 线与 MA5，在下方展示财务、公司概况、分红、股东、主营，以及系统已保存的估值、市值、质押、行业、证券风险与行情可用性数据。按数据集查看记录数、分页、展开全部来源科目；来源科目保留原始值，平台字段标注标准单位。加载失败可独立重试，不触发网络采集；尚未同步显示空状态。普通登录用户只读，采集与来源配置仍需管理员权限。

## 平台库与时间边界

```python
reports = context.library('financial.income-statements', symbol='000001', period='annual')
quarters = context.library('financial.financial-indicators', symbol='000001', period='quarterly')
balance_sheets = context.library('financial.balance-sheets', symbol='000001')
company = context.library('financial.company-profiles', symbol='000001')
# 其他数据集同样加 financial. 前缀；无记录时为空序列。
```

`period` 默认 `all`；`annual` 只选12月31日报告，`quarterly` 选非年报（含中报）。这里的“季报”仍是来源累计口径，不进行单季差分。`context.financials(symbol)` 兼容主要财务指标；`fundamental.history/latest` 也按报告期选择可见财务版本。快测、回测、实盘共用相同平台库与依赖识别，策略不会直接访问网络。

标准金额为报告币种的元（当前 A 股通常为 CNY）；每股为元/股，比例为百分数，例如 `roe=Decimal('8.07')` 表示8.07%，不是0.0807。`registered_capital` 由来源万元换为元，主营占比由小数换为百分数。字段单位见详情和接口 `fields`；策略中的标准数值为有限 `Decimal`，缺失为 `None`，不补零。完整原字段保留原始单位和口径，不能直接假设等于平台标准字段。

每条记录带 `report_period`、`report_type`、`statement_scope`、`period_basis`、`currency`、`source`、`published_at`、`source_updated_at`、`fetched_at`、`available_at`、`availability_basis`、`record_key`。

- 只有公告与来源修订时间均可核实时，`available_at` 才取两者较晚时间。只有日期或来源占位零点时，保守取上海时区当天23:59:59。
- 缺少公告或来源修订时间，按采集时间可见，不能用报告期或最初公告倒填最新修订值。新浪主要指标、公司概况、部分分红/户数/主营因此可能仅在采集后可用于策略。
- 内容哈希保留版本；重复采集相同内容不增加记录，也不改变首次采集及可见时间。相同报告内容发生变化、而来源未更新版本时间时，新版本从实际采集时点可见。
- 决策时点先过滤未来记录，再为各报告期选当时可见版本，按报告期升序输出。同一报告不混来源拼字段；可见时间相同时优先东方财富。旧年报晚修订不会覆盖新季报的“最新报告”位置。

原始来源通常只提供当前修订版，平台无法重建首次接入前已消失的旧版本。保守可见规则可能导致早期回测财务数据不足；不要通过修改 `available_at` 补足历史。

## 存储与运维

迁移 `0015_financial_records` 只将现有 `market_records.payload_json` 从8000字符扩为 TEXT，增加可空 `symbol` 列、从现存 JSON 回填及 `(symbol,dataset_key,available_at)` 索引。不新建数据表、外键，不修改 K 线表或 K 线数据。版本以报告期/事件存储，相同内容不会每天复制。详情查询使用标的索引、数据库计数和 LIMIT 分页，单页最多50条。

部署时先备份并安排现有基本面表的 ALTER/索引维护窗口，再执行根命令 `pnpm migrate`，随后重启 API 与 worker；这项代码交付没有替用户在真实库执行迁移或全市场回填。TEXT 扩容回退时不主动缩回8000字符，避免截断已保存报表。单只股票响应完整校验后再写入；某只失败会报告失败标的与来源尝试，其他成功股票保留，可按失败代码重试。

接口依据 [AKShare 官方财务文档](https://github.com/akfamily/akshare/blob/main/docs/data/stock/stock_finance.md) 及其适配器分析原站协议，源站为 [东方财富 F10](https://emweb.securities.eastmoney.com/PC_HSF10/NewFinanceAnalysis/Index?type=web&code=sz000001) 和 [新浪财经](https://quotes.sina.cn/cn/api/openapi.php/CompanyFinanceService.getFinanceReport2022?paperCode=sz000001&source=fzb&type=0&page=1&num=1)。2026-11-01已做12个来源/数据集组合只读探测；上游不是平台控制的稳定服务，协议变化时需更新适配器。自动测试全用版本化脱敏 fixture、MockTransport 与内存替身，不访问源站和真实存储。

盘后基础刷新失败保留已确认状态；聚合任务继续其他数据集，最终明确报告部分失败。页/标的失败有限退避，成功范围通过内容哈希与刷新检查点去重。源站持续不可用时不能保证采集成功，不伪造数据。
