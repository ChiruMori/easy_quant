# 实施计划

1. 依据 AKShare 官方财务文档及本地适配器核查原始接口，记录只读探测与字段/时间限制。以东方财富 emweb 三大报表、datacenter 指标/概况/分红/户数、主营接口和新浪 FinanceReport2022 形成直连适配器；复用现有来源重试、缓存及开关。
2. 建立供应商无关数据集、单位和时间契约；适配器在缓存前完成归一化及校验。同步服务保存内容版本并保留失败明细，复用现有任务分批执行和重试入口。
3. 扩展 market_records 的 payload 容量及 symbol 查询索引，迁移只涉及该基本面表，无新表/外键或日线变更。基于季度/事件记录，重复采集不新增相同内容，避免转为每日财报快照。
4. 平台库新增明确财报入口并完善历史版本选择、依赖识别及 Decimal 传递，原 financials 兼容；股票详情复用共享组件逐数据集读取当前已保存数据与历史完整字段。
5. 离线验证、当前文档、全量检查和受影响浏览器旅程后提交财务功能分支 PR。该能力范围独立于 UI PR #26，基于其股票详情代码；以 master 为目标并说明前置依赖。

宪章检查：仍限 A 股低频研究与人工建议；所有网络在可注入适配器；时间来自采集 envelope，领域不依赖环境时间；数据保留来源和修订，测试使用 MockTransport/fake/内存。迁移不访问日线、不加外键；运行期不伪造数据或执行交易，不增加服务/分布式组件。
