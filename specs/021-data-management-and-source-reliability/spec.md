# 数据管理布局与指数来源可靠性

- 指数同步必须校验真实响应、日期、字段和资金数据类型；HTTP 200、空响应或异常结构不得被记为成功并阻断来源切换，坏缓存同样要失效。全来源失败时任务失败，批量任务保留已完成标的并展示失败标的及原因，不补造行情。
- 实测所有主要指数的来源可用性，区分适配错误、网络不稳定与已停止维护。仅在有充分证据时移除来源，保留可工作的独立来源与启停配置。
- 股票和指数仅作为数据管理页两个 Tab；移除独立侧栏与重复指数入口，旧路径重定向兼容。股票 Tab 不混入指数。宽屏左标的右紧凑来源面板；窄屏数据在前、来源在后。
- 来源用带图标、文字和颜色的按钮展示启用状态；点击立即保存，等待期间防重复，失败回滚并反馈。移除保存按钮，保留服务端配置与重载一致性。
- 页头仅保留“数据维护”菜单，包含上传、停复牌刷新、范围拉取与整体维护，不重复摆放功能按钮。
- 建立当前项目 UI 规范，说明导航、布局、尺寸、语义色、表格、图标、自动保存、加载/失败/空态、可访问性及验证；临时小程序文件仅供文档结构参考，提交前删除。

验收：离线验证空/坏/过期响应的切源和缓存、全部指数适配、失败批次恢复；页面及 Playwright 验证 Tab、来源自动保存和失败恢复、维护菜单、1440/360px 无页面溢出；真实来源探测独立于自动化测试，记录公开证据和实测限制。
