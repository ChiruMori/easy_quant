# fix(data): 优化基本面批量采集与存储并新增股票报表

目标：master；来源：fix/fundamental-collection-reports。状态：提交1f29185已推送；本轮创建草稿PR再次返回 GitHub 连接器403，PR未创建。此前浏览器工具因当前 Firefox 不支持 URL 策略而停止。

证券清单及估值采集失败、提前分红公告导致整页拒收、重复证券状态和宽 JSON 存储使基本面采集难以持续运行。本次改为经过只读探测的新浪直连证券/估值分页，修正时间语义与增量检查点，并在股票详情提供财报和主营图表及单股报告期补采。

- 新浪清单包含沪深京，分页总数、重复代码、数值和万元转元在适配器边界处理；替换旧证券/估值目录及绑定，保留禁用设置和已有上市日期。聚合任务不再强制把证券限制为东方财富。
- 提前分红公告正常保存；其他提前公告保留原值并从采集时点可见。明确坏数据按股票/报告期报告，同页有效股票继续保存，失败范围不写成功检查点。修订选择比较真实时间点，兼容上海时间与 UTC。
- 已完成旧财报不再每30天全量重抓；近期报告复查，日线补尾并检测已有近五年内部缺口。旧缺口成功尝试后冷却30天，近期缺口每日复查；持久游标和检查点不清空。
- 主营构成采用已实测的全市场报告期分页（RPT_F10_FN_MAINOP，每页500条），保留原逐股字段与内容身份；近期30天复查、历史完成后跳过，旧任务游标一次性切换。实际分页上限不支持盲目扩容；未验证到前复权日线批量替代入口，因此保持日线口径。
- 证券状态按业务变化保存；重复观测不改变首次可见时间，停牌区间更正及状态回变仍保留。旧重复记录只读折叠，页面和策略口径一致。新大载荷无损压缩、旧 JSON 兼容，SQL所需元数据仍可直接投影；存在性预检使用LIMIT 1，运行输入在SQL限制可见时间，单股图表有读取上限。
- Recharts 展示归母净利润、收入、ROE、EPS等指标，支持报告类型/来源和主营报告期/分类/收入成本利润切换。累计季度不叠加、缺失不补零，提供数值表；管理员异步补采单股所选报告期，失败可重试，普通用户只读。
