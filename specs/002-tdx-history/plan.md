# 实现计划

使用 Python 标准库 struct/zipfile 与已有 httpx、SQLAlchemy/PyMySQL，无新增存储或服务。参考官方页面和 jing2uo/tdx2db 的二进制格式，自行实现适合现有 MariaDB 的适配器。

依次新增领域日线值对象与导入端口、通达信 ZIP 适配器、应用导入编排、MariaDB 批量 upsert/检查点及 CLI。为已存在数据库添加增量 Alembic 迁移，新增日线成交额、来源、不复权口径及原始包身份字段；新建导入股票检查点表，成功标记与组内行情及元数据同事务提交。批次重复写入保持幂等，未完成股票从头重放。

下载和摘要计算使用有界块，ZIP 按文件读取，一只股票数据可在内存预检；事务组达到约十万行或五十只股票时提交，默认 SQL 每次执行 2000 行（可配置至 10000）。远程数据库往返开销较大，CLI 支持显式使用服务器已有的 LOAD DATA LOCAL INFILE，API 默认关闭，不修改服务器全局配置。交易日历只补入缓存中未知的日期，缓存仅在提交成功后更新。全量写库前检查冲突复权口径。现有覆盖查询改用 group by，不读出全部日线。

真实导入发现 float32 成交额超过 Numeric(28,4) 的小数精度，适配器统一以 ROUND_HALF_UP 规范为四位小数，默认和原生导入使用同一数据值。任何原生数据库警告使批次回滚，错误输出只保留类型或代码，避免凭据与 SQL 参数泄露。

## 宪章检查

- 只接入日频决策辅助数据，不包含自动下单或高频。
- 领域仅使用确定性值类型；文件、网络、SQL 在适配器；时间和进度由边界传入。
- 数据明确不复权，保留来源、金额/量单位、时点与 ZIP 身份；重跑幂等，可恢复。
- 所有运行持久化使用已配置 MariaDB；测试显式 fake 且禁止真实网络/存储。
- 不保存数据库凭据到代码和日志；原始归档使用被忽略的 backend/.local-data。
- 行为、离线测试、当前文档同一变更；先完成设计、任务再实现。

完整历史仅指官方包实际提供的 A 股文件，不声称涵盖所有退市/更名证券或自动取得复权因子。官方包更新日与末交易日分别核验。

真实多百万行验证发现，聚合查询扫描聚簇主键仍需读取完整行情行，因此增加仅股票和日期的覆盖二级索引，以减少读盘；使用独立 `0003_history_coverage_index` 迁移，避免修改已执行的迁移行为。
