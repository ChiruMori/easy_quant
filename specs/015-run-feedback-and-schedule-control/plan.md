# 实施方案

沿用日线、单 worker、邀请制、受限策略子进程及人工交易，不增加服务、自动交易或分布式架构。领域资金与时间可见性不变。

1. AST 提取静态因子窗口，显式声明优先；运行区间持续流式推进，只缩减预热和滚动保留量。
2. 用已有覆盖索引做键列摘要校验，避免先执行完整策略才报端点缺失。上市日期调整覆盖起点；逐日数据仍按 available_at 过滤。
3. 为回测进度/失败写入注入独立 Session factory，读任务连接失效后回滚移除，失败不被二次异常取代。进度限定频率，并保存计时摘要和日 hook 记录。
4. 调度 API 加受限更新和幂等手动入队；沿用既有任务类型处理器。
5. API client 写请求订阅计数，在应用顶层挂载模态加载层，轮询不阻塞；页面展示结构化进度/计时/缺失及任务编辑/执行。

自动化验证仅使用内存 fake、固定 fixture 和本地端到端替身，不访问真实数据库或第三方网络。Living Docs 只描述已完成行为。
