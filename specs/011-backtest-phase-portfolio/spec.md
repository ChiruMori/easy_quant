# 回测阶段与模拟组合状态一致性

**状态**：已实现并通过离线验收

## 问题与范围

流式回测在一天开始时一次生成三个阶段的信号，再交给领域引擎成交。策略上下文没有组合状态，`context.position()` 始终返回零，现金也不可见。持仓条件策略会重复买入，后续阶段无法响应前一阶段已经发生的模拟成交。

本功能延续日线、单 worker、受限子进程和不可变策略版本，不增加外部服务或交易执行。

## 要求

1. 按盘前策略、盘前模拟成交、盘中策略、盘中模拟成交、盘后策略、盘后模拟成交的顺序推进。每个钩子读取该阶段开始时真实的模拟持仓和现金；跨日保留模拟组合。
2. 组合只根据领域引擎实际接受的成交变化。资金不足、持仓不足、未触价等未成交信号不改变下一阶段的组合。
3. 子进程仅收到 Decimal 的十进制字符串快照。资金与持仓的权威演算仍在纯领域引擎，策略不得通过修改上下文字典改变引擎组合。
4. 保持可获知时间、盘前/盘中收盘隔离、滚动历史、逐日源码全局状态重置和阶段间源码全局状态保留。策略失败时不发布部分成功的回测结果。
5. 保留现有无组合调用方的日 Tick 接口，并同步当前行为说明。既有回测结果不追溯改写，新回测保存组合上下文协议身份。

## 验收

- 盘前买入后盘中看到已成交持仓和扣除费用后的现金；盘中卖出后盘后看到更新组合，下一日继续正确推进。
- 以空仓为条件的策略只买入一次；未触价或资金不足的买单不会向后续阶段暴露虚构持仓。
- 修改子进程中的组合副本不影响后续成交或账户；相同输入重跑得到相同交易、权益和快照身份。
- 延迟日线、当日收盘隔离、长序列有界窗口、退市过滤和策略失败回收回归通过。测试完全离线。
