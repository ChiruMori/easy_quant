# 实施计划

## 宪章检查

- 保留低频日线、邀请制、人工实盘账本和既有单机架构，不增加自动下单或分布式服务。
- 领域引擎已提供逐阶段回调；利用该边界执行策略，不让领域代码依赖进程、网络、SQLAlchemy 或 Flask。
- Decimal 组合权威留在领域引擎，应用服务把阶段开始时的值编码为独立字符串副本，通过受限子进程通信。
- 保持行情时间隔离、策略版本不可变性和失败记录；离线 fake、内存仓储与真实受限子进程覆盖验收。
- 不新增数据库迁移、服务或缓存。完成后同步 Living Docs 和质量门禁。

## 设计

1. 扩展已有流式子进程协议，提供单阶段交换。盘前请求驱动当日历史过期和源码初始化，盘后请求追加当日与延迟可见行情；源码命名空间在三个阶段共享，在下一日重置。旧日 Tick 接口保留。
2. `StreamingStrategyRunner.run_phase` 返回一个阶段结果，沿用超时、传输上限和退出回收。各阶段顺序由子进程校验，错误阶段或跨日乱序明确失败。
3. 应用服务把策略调用放进 `PhasedBacktestSession.advance` 的阶段回调，从引擎当前组合生成现金及持仓副本。结果立刻交回引擎模拟成交，再运行下一阶段。
4. 保存 `phase-portfolio-v1` 作为新回测 assumptions 的上下文协议身份，不改写既有记录。快测及实盘接口保持当前行为。
5. 回归测试验证真实成交、未成交、跨日、Decimal 费用、隔离及可复现性。校正当前限制文档中已被远端性能功能淘汰的同步执行和全史加载说明。

## 边界

策略 `position()` 继续返回既有 float 类型，现金从 `context.data["cash"]` 读取十进制字符串；资金演算使用 Decimal。每个钩子看到阶段开始快照，同一钩子中多个信号提交之前不会更新快照。本功能不增加成本因子、初始持仓、回测 warm-up 或公司行为处理。
