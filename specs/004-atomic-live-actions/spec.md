# 人工建议处理的原子账本闭环

日期：2026-10-02。承接基础规格 FR-045、FR-049、FR-050，修复真实 API 绕过应用服务、先持久化后校验的问题。状态：实现与离线验收完成。

## 范围

确认、拒绝和修正建议先校验 Decimal 成交字段和候选账本，再在同一工作单元保存实际操作、账本、建议版本、组合缓存及审计。新账本具有明确入账序号，避免相同时间或时钟回退改变重建顺序。保持现有接口；页面展示失败原因、处理中和处理完成状态，成功后更新建议，防止重复点击。幂等键按用户隔离，同一键只允许重放相同建议及相同请求；失败不占用键。实盘分析读取账本重建结果，生成建议和暂停/终止操作不能覆盖已处理状态及组合缓存。

不加入自动下单、分布式组件、全市场回测优化、初始持仓迁移或历史坏账自动修复。现有初始现金账本口径保持一致；旧记录无法补全的成交字段不猜测。

## 验收

1. 资金不足或卖出超过持仓时返回 409，操作、账本、建议、组合缓存、审计均不改变；修正请求后可以再次提交同一键。
2. 十次相同请求返回相同响应，只产生一次账务变化和一条审计。另一建议、另一动作或不同成交字段复用键返回 409；其他用户的键独立。
3. 并发处理同一建议只有一个状态迁移；不同建议争用同一组合资金时按最新账本校验，不能产生负现金。
4. 任一步存储失败或提交失败时全部回滚，安全重试可以成功。
5. 确认、拒绝、修正及费用与持仓成本保持 Decimal 精度；拒绝没有成交账本。
6. 跨用户访问返回 404；未登录及缺 CSRF 请求被拒绝；未知动作、非有限数值不能写入。
7. 分析生成新建议时保留已经确认的旧建议；分析使用账本恢复的组合。
8. 页面显示资金冲突，允许修正重试；成功后立即显示已处理状态并禁用操作按钮。
9. 所有自动化验证通过 fake、内存状态及 SQL 编译完成，禁止访问真实数据库和网络。
