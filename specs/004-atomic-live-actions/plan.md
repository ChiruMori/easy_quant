# 实施计划

## 方案

应用服务通过 LiveTrackingStore 端口获得短事务状态，使用注入时钟和标识生成器。领域账本校验有限数值、费用、现金及持仓。API 只做认证、请求解析和服务调用。

MariaDB 适配器复用当前 runtime_documents 的已持久化状态，使用独立 Session、单个事务和事务内互斥行串行处理少量可信用户的人工反馈。互斥行由原子 upsert 创建并锁定，不引入分布式锁或额外中间件。事务内 JSON 仓储禁止自行 commit；错误回滚并关闭 Session。操作键使用用户与请求键的 SHA-256，兼容读取已有原始键，检查旧键归属与动作；因旧记录未保存请求身份，旧操作只展示现存状态，拒绝猜测重放。

生成建议时短事务重新读取并合并最新状态，已有建议优先；暂停/终止同样在端口内修改实例，以免旧缓存覆盖新持仓。策略计算和外部通知在短事务之外。全部领域规则可离线验证，内存适配器深复制状态并仅在成功退出时替换，使用同一互斥语义。

## 宪章检查

- 决策辅助及单机：PASS，仅人工记账，复用 MariaDB，无新服务。
- 领域隔离及契约：PASS，端口注入存储、时钟、ID；领域无 I/O。
- 时间及金额：PASS，注入 UTC 时间，Decimal 有限数值与账本重建。
- 原子、幂等、审计：PASS，校验后一个事务，用户隔离键及请求身份检查。
- 权限与凭据：PASS，服务再次检查归属，不存储凭据。
- 离线测试及 Living Docs：PASS，fake 存储、故障注入、SQL 编译和本地 Playwright；实现后更新 docs。
- 因子与策略生命周期：PASS，不改变。

## 限制及退出路径

这是现有持久 JSON 状态的事务修复，暂不迁移到结构化实盘表。全局短事务串行化适用于少量人工请求；回测与行情导入不使用该锁。历史无效账本不自动删除或修正，遇到时继续阻断并要求人工核验。初始持仓基线和完整成交时间/备注表单留待独立规格。后续结构化迁移可替换同一端口。

页面复用 shadcn Alert 展示错误、Button disabled 表示处理中或已处理。网络失败后的相同请求保留幂等键；成功后用保存响应更新状态和版本。暂停/终止合并返回字段，保留建议列表。
