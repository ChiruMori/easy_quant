# 实施计划

## 宪章符合性

- 仍为单机 MariaDB job 表和现有 worker，不新增队列或缓存服务。
- 不改变策略时点、因子/策略边界或用户权限；只修正 job 存储容量和管理员列表导航。
- 数据库变更使用顺序 Alembic 迁移，保留已有记录；测试使用 SQL 编译和内存仓储，不连接真实数据库。
- Living Docs 仅在实现和验证完成后记录实际行为。

## 方案

1. 将 `jobs.id` 扩至 64 字符，新增 `0006` 迁移；保持既有带前缀 ID，不更改 API 关联字段或业务键。
2. 覆盖列表加入 `after`/`before` 代码游标。无状态筛选时顺序翻页使用主键范围加 LIMIT，直接跳页使用仅投影股票代码的定位查询。状态筛选仅按索引聚合首末日期，不做逐日 COUNT；由于当前目录约 6,000 项，单次读取匹配的代码并在内存中定位目标页，避免对大型日线聚合重复运行计数和分页查询。详情及日线记录仍只读取目标页。总数用于约束页码。
3. 页面提供数字页码输入、跳转、前后翻页和越界反馈；搜索、状态筛选时清空游标并返回首页。
4. 验证 ID DDL、分页 SQL 形态、API 响应、前端交互和浏览器旅程；按仓库门禁格式化、检查与测试。

## 权衡

任意页码跳转不能完全用单个 keyset 游标实现。无状态筛选时偏移仅作用于窄的股票代码投影，常见顺序翻页不使用 OFFSET；状态筛选则只在应用层对至多约 6,000 个代码定位，不把完整行或日线明细传到前端。若目录规模显著扩大，可再引入事务维护的覆盖汇总表。
