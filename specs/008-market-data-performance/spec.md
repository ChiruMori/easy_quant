# 行情读取与策略运行性能治理

## 概述

现有 `daily_bars` 约 1,800 万行。单日快测实际仅查询 6 个交易日、约 3.3 万行，却耗时约 7 分钟；实盘路径无历史下界，回测路径对已加载历史反复全量扫描。优化必须在不引入未来数据、不改变策略版本身份和资金演算口径的前提下完成。

## 功能要求

1. 快测仍只运行用户指定的一天和盘前、盘中、盘后三阶段，读取此前 5 个实际交易日；在代表性 3.3 万行窗口、已完成部署索引及合理数据库缓存配置下，预热后目标为 5 秒内。运行日志记录分阶段耗时与行数，不记录策略源码、参数、凭据或信号内容。
2. 行情读取不得为因子不需要的列反复回表。所有针对 1,800 万行表新增、删除或替换的索引必须有现有查询、`EXPLAIN`、读写成本与迁移风险依据；迁移必须可回退。不得在未记录设计依据和用户确认前实施分表或拆分存储。
3. 同一运行中多次请求重叠行情时，使用有界内存页缓存，缺页按明确的交易日区间批量读取，命中时不重新访问数据库，满额按 LRU 淘汰。缓存不得跨越数据修订边界产生陈旧结果；内存上限和失效语义应可测试。优先复用成熟实现，不引入无必要的 Redis 服务。
4. 实盘监控默认只读取决策日及此前 250 个交易日；策略可在不可变源码中显式声明更长窗口，受安全上限约束。回测的策略因子上下文也使用同一有界回溯，但回测区间本身不受限。仍遵守 `available_at` 可获知时间和阶段隔离。盘中一次分析在代表性数据量下目标不超过 2 分钟。
5. 多年回测不得将所有已同步历史反复扫描或按交易日重复拉取同一页；时间复杂度随处理行数和交易日近似线性增长。代表性完整多年回测目标为 10–30 分钟，内存使用有界，原有快照、指标、交易和可复现性契约不退化。
6. 所有自动化测试离线运行，覆盖缓存命中、缺页、LRU 淘汰、时间可见性、索引查询形态、长回溯声明和回测结果等价；真实数据库计时只作为只读诊断或受控迁移后的人工验收。

## 用户场景与验收

- 用户点击“运行当前版本”后，worker 在日志中分别报告取数、构造上下文、策略子进程和保存结果的耗时；从已预热的代表性行情库中数秒内得到信号与标准输出。
- 用户运行实盘盘中监听时，默认不会读取全表；指定更长回溯的策略按声明读取，超过安全上限明确报错，不静默截断。
- 用户运行多年回测时，处理历史数据不会因交易日增加而出现二次方扫描；相同输入仍产生相同回测结果和快照身份。
- 维护者运行迁移前可看到目标索引预计空间、维护窗口与回退步骤；无证明的重复索引不得盲删。
