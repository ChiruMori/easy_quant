# 实施计划

## 技术背景与实测

- 运行环境：Python 3.13、SQLAlchemy 2、PyMySQL、MariaDB 10.6；单机 API + 单 worker，`daily_bars` 约 1,818 万行。数据库缓冲池 128 MiB，数据约 3,293 MiB、索引约 593 MiB。
- 2026-09-04 快测查 2026-08-28 至 09-04 的 33,282 行。现有 `(trading_day,symbol)` 索引 `EXPLAIN` 为 range；索引内两列读取约 0.8 秒，带价格与可获知时间的查询约 29 秒，整个策略约 31 秒。用户所见冷读约 7 分钟。瓶颈是非覆盖索引引起的大量随机回表，因子循环没有重复访问数据库。
- `ix_daily_bars_coverage(symbol,trading_day)` 目前支撑覆盖率聚合及筛选，不能仅因与主键前缀相同就删除；现有日期索引需由覆盖型运行索引替换，避免保留两个同前缀日期索引的写入开销。
- 回测当前预载所有行，按每只股票及每个交易日反复扫描；实盘当前无历史查询下界。这两项与数据库读取同属性能问题。

## 宪章符合性

- 只优化低频日线读取、策略分析和回测；不增加高频行情、自动下单、公共注册或分布式服务。
- 受限子进程仍是动态策略唯一执行边界；领域回测保持纯计算，不依赖数据库、Flask 或环境时钟。
- 行情查询和页缓存属于基础设施，缓存仅在一次任务内存活，沿用同一数据库事务快照；跨任务重新读取，不需要跨进程失效协议。自动化测试使用 fake 仓储，不访问真实数据库。
- 时间窗口以交易日历计算，再按 `available_at` 做决策时点过滤；不能把今日收盘提供给盘前/盘中。
- 不实施分表或拆分存储。如覆盖索引、分页和数据库配置后仍未达标，再另立规格并向用户确认。

## 设计决策

1. 新增可回退的覆盖索引 `(trading_day,symbol,available_at,open,high,low,close)`，替换 `ix_daily_bars_day_symbol`。运行期只投影这些列，保证快测、实盘及回测 OHLC 查询为 index-only；保留旧覆盖率索引用于股票覆盖统计。迁移在 18M 表上可能耗时和占临时空间，部署文档要求维护窗口、备份、先确认剩余空间，并在迁移后 `EXPLAIN` 出现 `Using index`。开发期间只做只读查询，不自行在正在服务的用户数据库运行大表 DDL。
2. 使用 Python 标准库 `functools.lru_cache` 的单任务日线分页读取器，按交易日整页获取全市场日线，最多保留 12 页。所有策略因子请求共用该次任务的页面/派生价格视图；不引入 Redis，因为单 worker 中跨任务缓存失效会与 API 导入冲突，收益也无法消除首次冷读。
3. 在策略源码顶层允许 `HISTORY_TRADING_DAYS = N`，默认 250，范围 1–2500；快测仍固定 5 日。实盘与回测策略上下文按该滚动窗口提供日线，回测区间仍可覆盖多年。显式限制替代原先实盘隐式全史读取，界面和文档解释兼容变化。
4. 回测按交易日顺序读取行情，不再反复扫描 `stored_rows`。按当前日构造盘前/盘中/盘后上下文；领域引擎增量推进组合。历史价格只保留声明窗口，数据快照通过临时文件流式规范化、哈希及压缩写入，避免全史字典和 JSON 同时驻留内存。
5. 对耗时较长的回测，策略子进程保持单任务生命周期，按交易日交换小批量输入，子进程维护滚动历史；每个 Tick 限时，失败时回收子进程。快测可继续使用现有一次性子进程。
6. worker 日志增加行情读取、上下文准备、子进程和快照保存计时，以及行数/页缓存命中数；只输出数值与 job ID，不输出任何策略代码、参数、信号或数据源凭据。

## 风险、回退与验收

- 覆盖索引预计比旧日期索引更大，增加导入写入成本；迁移先加新索引、验证后再删旧索引，失败时保留原索引；升级需维护窗口，不在开发诊断时自动执行。`pnpm migrate` 可执行 downgrade 恢复旧索引。
- 任务内 LRU 页面按交易日而非示例中的按股票月份切分，因为当前样例每次遍历全市场；按股票月份会产生约 6,000 次查询。独立的单股图表保留主键范围查询。12 个交易日页通常约 7 万行，避免缓存整个 18M 表。
- 滚动窗口是显式行为变化：此前依赖实盘全史的策略需声明更大 `HISTORY_TRADING_DAYS`；超出安全上限直接校验失败。回测原有全史上下文也改成明确上限，需以 fixture 对示例和长周期策略验证结果。
- 在真实数据库上只读复测快测和盘中路径，记录冷/热耗时及 `EXPLAIN`；覆盖索引尚未部署时不得宣称 5 秒目标已达成。回测以合成长期数据验证近线性扩展和等价资金结果，再安排真实多年验收。
